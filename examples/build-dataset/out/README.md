# CPython 3.9.6 standard library: code corpus and docstring pairs

## Dataset summary

A small, fully reproducible example of building a documented code dataset. The source is the Python 3.9.6 standard library source tree (Python files only). The dataset has two configurations:

- `code_corpus`: 588 whole files with provenance, license and hash fields, about 2,338,183 estimated tokens (characters divided by 4).
- `docstring_pairs`: 3471 instruction-response pairs. The instruction is a function's docstring plus its signature line; the response is the function without its docstring.

It is a teaching example, not a training set for a serious model. Total size of the data files: 13.3 MB. The pipeline that produced it (`01_collect.py` to `07_card.py`) is in the `examples/build-dataset` folder of the Renaissance Labs code repository; this card was generated by `07_card.py` from the run's own logs.

## Provenance

- Source tree: `cpython-stdlib`, version 3.9.6, read from the local Python installation on 2026-11-25 (retrieval date recorded in each file's provenance). Nothing was downloaded or cloned.
- License file read from the tree: `LICENSE.txt`, sha256 `599826df92bfdcd2702eac691072498bb096c55af04ee984cf90f70ed77b5a70`. Check: LICENSE.txt contains 'PYTHON SOFTWARE FOUNDATION LICENSE VERSION 2'.
- Files seen: 682. Skipped: 6 not valid UTF-8, 2 over 200,000 bytes. Kept for processing: 674.
- Each `code_corpus` record carries `path`, `repo` (the top-level package or module), `license`, `sha256` of the released content, `source_sha256` of the original file, and `source_version`.
- The top-level `test` directory is absent in this tree; only package-internal test directories exist (`sqlite3/test`, `tkinter/test`). Test-file pairing was therefore dropped, and test files are not separated from other code.

## Licensing and what may be redistributed

The standard library is licensed under the Python Software Foundation License Version 2 (SPDX `PSF-2.0`). It permits copying, modification and redistribution if the license text and the PSF copyright notice are kept and a brief summary of changes is included in derivative works. The unmodified license file is shipped in this repository as `LICENSE`.

Per-file licenses in the released `code_corpus`:

- `Apache-2.0`: 2 file(s)
- `MIT OR Apache-2.0`: 1 file(s)
- `PSF-2.0`: 585 file(s)

Some files carry their own license header (a third-party author). Detection is a header regex, not a legal review. 14 files whose header matched a permissive-style notice that is not mapped to an SPDX identifier (1 x LicenseRef-BSD-style, 13 x LicenseRef-HPND-style) were excluded by the license gate until a person reviews them.

Summary of changes (as the PSF license asks): 127 of the 633 files that reached the scrubber were modified by the scrubber (placeholders for e-mail addresses, password-like literals and global IPv4 addresses; counts under Processing steps). Files were otherwise copied verbatim, with line endings normalized to LF. Comments, docstrings and copyright headers inside files are unchanged except for those replacements.

The `license` field on this card is `other`, because the Hub's license list has no PSF-2.0 entry and the data mixes licenses per file. Anyone redistributing must keep the per-file `license` field and `LICENSE` with the data. This card is not legal advice.

## Processing steps

Counts are from this run (`out/logs/stage_*.json`).

| Step | What | In | Out | Dropped or changed |
|---|---|---|---|---|
| 01 collect | files seen | 682 | 674 | non-UTF-8 6, over cap 2 |
| 02 filter | quality rules and license gate | 674 | 633 | quality 27, license gate 14 |
| 03 scrub | secrets and personal data | 633 | 633 | 127 files changed |
| 04 dedup | exact then MinHash/LSH | 633 | 589 | exact 0, near 44 |
| 05 split + decontaminate | group split, 13-gram filter on train | 589 | 588 | train removed 1 |
| 06 format | records written | 588 | 588 corpus, 3471 pairs | pairs from docstrings |

Details:

- Quality filters, files dropped by the first failing rule: min size 24, max lines 0, max line length 0, average line length 0, alphanumeric fraction 0, auto-generated header 3.
- License gate: allow-list `allowed_licenses.json`; dropped 14 files.
- Scrubbing replacements: private key blocks 0, AWS access key ids 0, GitHub tokens 0, password-like assignments 1, e-mail addresses 163 (in 119 files), global IPv4 addresses 10. Loopback, private and documentation IPv4 addresses (80) were kept. After scrubbing, 633 of 633 files that parsed before still parse; newly unparseable: 0.
- Dedup: exact duplicates removed 0; near duplicates (MinHash, 64 permutations, 16 bands of 4 rows, token 5-shingles, exact Jaccard >= 0.8 to confirm candidates) removed 44 in 16 clusters. Clusters are transitive: a file can join a cluster through a neighbor even if its direct similarity to the kept file is lower.

## Splits

Split by repository group (top-level package directory or top-level module) with a stable hash (`sha256(salt:group) mod 100`: below 80 train, 80 to 89 validation, 90 to 99 test). Related files never straddle splits.

| Split | Groups | Files | code_corpus records | docstring_pairs records | Estimated tokens |
|---|---|---|---|---|---|
| train | 152 | 523 | 523 | 2909 | 2005781 |
| validation | 16 | 16 | 16 | 244 | 125272 |
| test | 22 | 49 | 49 | 318 | 207130 |

Group overlap between splits: 0 (check passed: True). Split sizes depend on which groups the hash assigns, so validation is small. `out/split_check.json` lists the groups per split.

## Schema

`code_corpus`

| Field | Type | Meaning |
|---|---|---|
| id | string | first 16 hex of sha256 of source_version/path |
| repo | string | group: top-level package or module |
| path | string | path inside the stdlib tree |
| language | string | always `python` |
| license | string | SPDX id or expression for this file |
| sha256 | string | of `content` as released |
| content | string | file text after scrubbing |
| n_tokens_estimate | int | ceil(characters / 4) |
| split | string | train, validation or test |
| source_version | string | tree name and version |
| source_sha256 | string | of the original file bytes |

`docstring_pairs`

| Field | Type | Meaning |
|---|---|---|
| id | string | first 16 hex of a sha256 over source id and function name |
| instruction | string | docstring plus signature line |
| response | string | function text without its docstring, dedented |
| source_id | string | `id` of the `code_corpus` record it came from |
| license | string | license of the source file |
| split | string | inherited from the source file |
| qualname | string | function name, with class prefix for methods |

## Known limitations

- One language (Python), one source, a few hundred files. Not enough to train a model; it shows the process.
- The corpus is a single project. Style, topics and Python 3.9 idioms are not representative of code in general.
- The regex scrubber misses secrets with no recognizable format, personal names, usernames in paths, and information that appears in prose. It also replaces harmless strings (author e-mail addresses in headers, example addresses). Stronger tools: the BigCode PII pipeline, detect-secrets, gitleaks.
- The auto-generated header rule can fire on prose (for example a file that mentions a generated parser).
- License detection by header regex is a heuristic. Docstring pairs inherit the license of the source file.
- Near-duplicate clusters mostly come from the `encodings` codec files, which share long boilerplate. Removing them keeps one codec per cluster, so some codecs are absent.
- The decontamination check only covers the evaluation file named below.
- Docstring pairs are filtered by length and line count; very short and very long functions are absent. Methods keep their original indentation relative to the class (dedented to the function).

## Contamination checks

- Eval file: `eval_probe.jsonl`, three hand-written benchmark-style problems; 444 13-grams indexed.
- Train files removed for sharing a token 13-gram: 1 (colorsys.py: 220 13-grams with probe-02). The planted overlap (problem `probe-02` reuses `colorsys.rgb_to_hsv`) was detected.
- Validation or test files overlapping the eval file (kept, never trained on): none.
- This check is a pipeline demonstration. Run `decontaminate.py` with the real benchmark files (HumanEval, MBPP, and so on) before training anything.
