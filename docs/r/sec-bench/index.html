SEC-bench

Real software vulnerabilities packaged as reproducible Docker instances, with two tasks: write a proof-of-concept input that triggers the bug, and write a patch that fixes it. From NeurIPS 2025.

How to use it

For evaluation and defensive research. Use the patching task for a defensive measure and keep proof-of-concept runs inside the containers.

Caveats

The README recommends more than 200 GB of disk for Docker images. The paper abstract reports at most 18.0% on proof-of-concept generation and 34.0% on patching at release. The lang column reads c++ for all 300 eval rows. GitHub last commit 2026-01-27.
