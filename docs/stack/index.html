The stack: from sand to trained models

A computer is built in levels. Each level is made entirely out of the one below it, and offers the one above a simpler, more powerful set of things to work with. A programmer at any level can mostly forget the levels underneath. That forgetting is what makes software possible, and understanding code means knowing what was forgotten.

One addition, all the way down

Adding two numbers looks like a single act. Followed down the stack, it is the same request restated six times, each time closer to the physics.

  1. Applications
    In a spreadsheet=A1+B1

    A person asks for a sum.

  2. Languages
    In Pythona + b

    A programmer writes the same request in a general language.

  3. Compilers
    In Python's virtual machineBINARY_ADD

    The compiler has turned the line into an instruction for an imaginary processor (the name is from Python 3.10 and earlier; newer versions call it BINARY_OP).

  4. Machine code
    In the real processoradd w0, w1, w0

    Compiled C, here for a 64-bit ARM chip. One instruction, stored as the number 0B000020 in hexadecimal.

  5. Logic gates
    In logic32 full adders

    In the simplest design, the instruction switches on a circuit that adds two 32-bit numbers one column at a time, passing carries along. Real processors use faster adders.

  6. Transistors
    In mattercharge moves

    At least a thousand transistors open and close for the addition itself, and many more fetch, decode and store the result. The answer is a pattern of voltages.

No level contains the meaning of the one above. The transistors do not know they are adding, the adder does not know it serves Python, and Python does not know it is totaling an invoice. Each level only keeps a promise to its neighbor. Software is that tower of promises.

How to read the map

The top of the stack is where intent enters and the bottom is where physics takes over. Programming languages are placed at the level where they most characteristically work, though many reach across several. Each level's page explains the one idea that level contributes, lets you operate a working model of it, and lists the open resources for training models to write code there.

The numbers on the right are entries in our verified catalog. They fall away steeply toward the bottom of the stack. Models have been taught to write Python functions far more thoroughly than to write hardware or reason about a network.
