Logic: from switches to arithmetic

How do switches add two numbers?

Wire a few transistors together and you get a gate: a circuit that computes one tiny logical function. AND gives 1 when both inputs are 1. OR gives 1 when either is. NOT flips its input.

In his 1937 master's thesis Claude Shannon showed that the algebra George Boole had devised for reasoning about true and false describes circuits of switches exactly. From then on, designing a circuit was a problem in logic. Any function from bits to bits can be built out of gates, and in fact out of a single kind, NAND, used over and over.

Two more ingredients make a computer. Feed two gates' outputs back into each other's inputs and the circuit can hold a bit: memory. Add a clock that ticks, and the circuit can step from one state to the next. Arithmetic, memory and sequence are then all present, and nothing above this level adds a new capability. Everything above is organization.

Hardware is itself designed in code. A hardware description language such as Verilog or VHDL describes a circuit as text, which tools turn into gates. It differs from software in one deep way: it describes things that all happen at once, not a list of steps.

Adding in binary

Adding 100 and 58 by hand in binary works like addition in decimal: add each column, write the low digit, carry the rest.

binary
    0110 0100     100
  + 0011 1010      58
  -----------
    1001 1110     158

One column needs a circuit with three inputs (two digits and the carry in) and two outputs (the sum digit and the carry out). That circuit is called a full adder, and it can be built from nine NAND gates. Eight of them in a row add two 8-bit numbers.

What to notice
  • Set A to 255 and B to 1. The carry ripples through all eight stages, and the answer has to wait for it. Fast processors use cleverer adders for exactly this reason.
  • Push the sum past 255. The ninth bit has nowhere to go, and the result wraps around. Integer overflow, a source of real software bugs, begins here.
  • Nothing in the circuit knows what a number is. It combines bits by fixed rules, and we read the result as arithmetic.

Central ideas

Logic gate
A small circuit computing a logical function of one or two bits.
Boolean algebra
The algebra of true and false, with operations AND, OR and NOT.
Truth table
A list of a circuit's output for every combination of inputs.
Universality
The fact that every logical function can be built from NAND gates alone.
Combinational logic
Circuits whose output depends only on the current inputs, such as an adder.
Sequential logic
Circuits with memory, whose output also depends on what happened before.
Flip-flop
A circuit that stores one bit and changes it only on a clock tick.
Hardware description language
A language for describing circuits as text. Verilog and VHDL are the main ones.
Synthesis
Automatic translation of a hardware description into gates.

Landmarks

  1. 1854
    The Laws of Thought George Boole

    Boole's An Investigation of the Laws of Thought (London, 1854) built an algebra of logic in which class symbols take only the values 0 and 1, the algebra that digital gates later implemented. source

  2. 1937
    Switching circuits as Boolean algebra Claude Shannon, MIT

    Shannon's master's thesis, written at MIT in 1937 (the MIT record lists the degree year as 1940) and published as a paper in Transactions of the AIEE, vol. 57, no. 12, 1938, showed that Boolean algebra can describe and simplify relay circuits and that relay circuits can solve Boolean problems. source

  3. 1966
    Computer-aided design for chips James Koford and colleagues, IBM Fishkill

    In 1966 the IBM Fishkill group used graphical displays to capture circuit module designs, check them for errors and convert them automatically into mask patterns, the start of the design-automation tools that later hardware description languages and synthesis built on. source

  4. 1979
    Introduction to VLSI Systems Carver Mead (Caltech) and Lynn Conway (Xerox PARC)

    Their textbook, which the Computer History Museum says demystified chip design for system designers, was published in 1979 (the museum's catalog record lists 1980), and made structured chip design teachable outside the semiconductor companies. source

  5. 1985
    Field-programmable gate array Ross Freeman, Xilinx

    Freeman's patent (priority date March 12, 1984) described an integrated circuit with user-programmable logic functions and interconnects, and Xilinx introduced the first commercial FPGA, the XC2064 with 64 programmable 4-input logic functions, in 1985, so that logic could be configured after fabrication. source

  6. 1995
    Verilog standardized IEEE

    IEEE Std 1364-1995, approved by the IEEE board on December 12, 1995, was the IEEE Standard Hardware Description Language Based on the Verilog Hardware Description Language, giving hardware designers a standard textual language for gates and registers (it was superseded by 1364-2001). source

Open problems and frontiers

  • Minimum circuit size

    Whether it is NP-hard to find the smallest circuit for a given truth table (the Minimum Circuit Size Problem) is a long-standing open question; Hirahara proved NP-hardness in 2022 only for the partial-function variant and under randomized reductions. source

  • Speculative execution as a hardware security hole

    The 2018 Spectre paper showed that speculative execution can be induced to leak secrets, affecting processors from Intel, AMD and ARM, and argued that lasting fixes need changes to processor designs and instruction set architectures. source

  • Comprehensive verification of whole processors

    A 2025 paper presents what its authors call the first comprehensive formal verification of a RISC-V processor with CHERI capabilities (CHERIoT-Ibex) against its Sail specification; extending proofs of this kind to larger, more complex designs remains open. source

What this means for training models

Hardware description is a real and growing target for models, with its own benchmarks. A model is asked to write a Verilog module, and the result is simulated against a testbench, the hardware equivalent of a unit test.

Open training data is scarce next to software. Most serious chip designs are proprietary, and the public Verilog on code hosts is far smaller than what exists for Python. Mistakes are also far more expensive: a bug in software is patched, while a bug in a manufactured chip can be fixed only by a new design, or worked around. Formal verification is routine in hardware for that reason, and it gives models at this level an unusually strong checker to learn against.
