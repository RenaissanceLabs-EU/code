Machine code: the instructions a processor understands

What does a processor actually do?

A processor is a circuit that does one thing for as long as it has power: fetch the next instruction from memory, work out what it says, carry it out, move on. Instructions are numbers. The list of numbers a given processor understands, and what each one does, is its instruction set. Three families cover most of the world's machines: x86-64 in desktops and servers, ARM in phones and a growing share of everything else, and the open RISC-V.

Individual instructions are tiny. Add two registers. Copy a value from memory. Compare two numbers. Jump to another address if the comparison came out a certain way. Everything any software does is built from steps of that size.

The idea that organizes all of it is the stored program. In most computers instructions are kept in the same memory as data, in the same form. A program is therefore data: it can be loaded, copied, sent, and written by another program. That is what lets one machine change jobs by loading a new program, and it is what makes compilers possible. It is also what makes some attacks possible, when data supplied by a stranger ends up being run as instructions.

Assembly language is machine code with names in place of numbers, one line per instruction.

Euclid's algorithm in ARM machine code

The C version of gcd, compiled by Clang for a 64-bit ARM processor. On the left, the 32-bit word that encodes each instruction (in memory its lowest byte comes first). On the right, the same thing in assembly:

ARM64 machine code and assembly
340000e1    cbz   w1, done        if b is zero, skip to the end
aa0103e8    mov   x8, x1          keep a copy of b
1ac10809    udiv  w9, w0, w1      q = a / b
1b018121    msub  w1, w9, w1, w0  b = a - q * b   (the remainder)
aa0803e0    mov   x0, x8          a = old b
35ffff81    cbnz  w1, loop        if b is not zero, go around again

This processor has no instruction for remainder. The compiler builds a % b from a division, a multiplication and a subtraction. The loop itself is five instructions, 20 bytes, plus the test before it.

What to notice
  • The program is the 16 bytes in the left column. The names beside them are for you. The processor sees only the numbers.
  • "pc" is the program counter: the address of the next instruction. A jump is nothing more than writing a new number into it.
  • This version finds the greatest common divisor by repeated subtraction, because the machine is too simple to divide. Simpler hardware means longer programs.

Central ideas

Instruction set
The complete list of instructions a processor understands. The contract between hardware and software.
Register
One of a few very fast storage slots inside the processor.
Memory address
The number that identifies one byte of memory.
Program counter
The register that holds the address of the next instruction.
Fetch, decode, execute
The cycle a processor repeats: read an instruction, interpret it, carry it out.
Stored program
Keeping instructions in the same memory as data, so programs can be handled like any other data.
Assembly language
A readable notation for machine code, one line per instruction.
Executable
A file of machine code in the format an operating system knows how to load.

Landmarks

  1. 1945
    First Draft of a Report on the EDVAC John von Neumann

    The draft, dated June 30, 1945, is described by Brian Randell as the first documented discussion of the advantages of using one large internal memory for both instructions and data, which is the stored-program idea (credit for the ideas among the EDVAC team is disputed). source

  2. 1964
    IBM System/360 IBM

    Announced on April 7, 1964, it replaced five incompatible product lines with one compatible family under a single architecture, so software written for one model ran on any other, and it pioneered the 8-bit byte. source

  3. 1978
    Intel 8086 Intel

    Introduced in June 1978 as Intel's first 16-bit microprocessor with about 29,000 transistors and the first chip of the x86 series, whose instruction set remains the basis of most desktop and server processors. source

  4. 1980
    The case for the reduced instruction set computer David Patterson and David Ditzel

    Their paper in ACM SIGARCH Computer Architecture News vol. 8, no. 6 (October 1980) argued for the reduced instruction set computer and began the RISC versus CISC debate over what an instruction set should contain. source

  5. 1985
    ARM1 Sophie Wilson (instruction set) and Steve Furber (chip design), Acorn Computers

    The first ARM chip was delivered to Acorn on April 26, 1985. source

  6. 2010
    RISC-V Krste Asanovic, Yunsup Lee and Andrew Waterman, UC Berkeley

    The instruction set was started in May 2010 in Berkeley's Par Lab as a royalty-free open standard, so anyone can build compatible processors without licensing an instruction set. source

  7. 2017
    WebAssembly WebAssembly Community Group (Chrome, Edge, Firefox, WebKit)

    In November 2017 the browser vendors agreed the design of the initial WebAssembly binary format was complete, and it became a W3C Recommendation on December 5, 2019, a portable binary format. source

Open problems and frontiers

  • Side channels from speculation

    The Spectre authors argue that processor-specific workarounds help only in some cases and that lasting fixes need changes to processor designs and instruction set architectures, so which security guarantees an instruction set should promise about timing and speculation is open. source

  • Memory safety in the instruction set

    CHERI extends instruction sets with hardware capabilities to protect against spatial, referential and temporal memory-safety flaws in C and C++; its main deployed prototype, Arm's Morello, is experimental, and bringing CHERI-RISC-V to market is under way as of 2024 projects. source

  • The hardware boundary of proofs

    seL4's machine-checked proofs run down to binary code but assume that assembly code, boot code, the machine interface, hardware and DMA behave as modeled, so connecting software proofs to verified hardware is an open frontier. source

What this means for training models

Open training data thins out sharply here. Assembly is a small share of public code, and what exists is scattered across processor families. The best-developed task is decompilation: given machine code, recover readable source. It has a natural check, since the recovered source can be recompiled and run against the original.

Binary analysis for security is the other main use: finding vulnerabilities in programs for which no source is available. Models that read and write machine code well would matter a great deal, in both directions, which is one reason careful evaluation at this level is worth having.
