About this site

How the maps were made, how every fact and entry was verified, what is missing, and how to correct us.

What this is

Renaissance Labs Code is a map of what code is, with working resources attached. It has four maps and one practical section. What a program is follows one small program through the eight forms it takes, from text to proof. The stack covers the nine levels a computer is built in, from transistors to trained models. The languages places 44 programming languages on that stack. Code in the world collects sourced facts about the software society depends on. The Train section is a verified catalog of datasets, benchmarks, environments and tools for teaching models to write code, with a recipe builder and a guide.

The idea is that the two halves need each other. You cannot train a model well on something you do not understand, and the checks that make code trainable (parsing, types, tests, proofs) are the same things that explain what code is.

How the figures work

The interactive figures are not animations. The program figures run on a small language implemented for this site: a lexer, a parser, a type checker with inference, a compiler to bytecode and a stack machine, about 300 lines of JavaScript that you can read at /lang.js. What a figure shows is computed from what you type. The neural network on the learned programs page is trained in your browser, and the adder, the processor and the cellular automaton are simulated, not drawn.

How the maps were verified

  • Languages: years, designers, influences and the systems said to be written in each language were read from official sites, specifications, the designers' own pages and repository statistics on the date shown. Each language page lists its sources. The sample program on each page was run on a real toolchain where one was installed, and the page says whether it was.
  • Landmarks: each dated landmark links to the paper, standard or archive it was checked against.
  • Code in the world: every fact links to its source with a date. Numbers that could not be traced to a readable primary source are not used.
  • Code samples in the text: the machine code and bytecode shown were produced on the day by the real compilers named beside them. The Lean proof was accepted by Lean 4.
  • Filing: catalog entries are placed under forms and levels by written rules plus hand corrections. Language coverage counts only languages that a resource's own documentation lists. Where the documentation is silent, the resource is not counted for any language.

How catalog entries were verified

Every entry was checked against a primary source on the date shown on its page. Licenses, sizes and activity come from the Hugging Face API, dataset and model cards, the GitHub API, papers and official documentation. When a field could not be confirmed, it is left empty and the caveats say so. Nothing in the catalog was filled in from memory.

  • Links: every external link in the data files was requested before release. The result is recorded in the repository (notes/link-report.json).
  • Snippets: commands and code on this site were matched to the tool's current documentation or run locally. Each one says how it was verified and which version was seen. Anything that could not be confirmed was left out.
  • Scores: this site does not publish leaderboards. Where a number appears, it names its source in the entry. Scores change quickly: go to the benchmark's own leaderboard.

What it does not cover

  • It is a curated selection, not every dataset on the Hub. Counts on the home page describe this catalog, not the field.
  • Licenses are summarized, not interpreted. The license family shown in filters is derived from the license text and is only a hint. Read the source license, and ask a lawyer when it matters.
  • Training advice is a starting point. Data mixes and hyperparameters that work for one base model can fail on another. Your own measurements decide.
  • Safety: running model-written code is dangerous. The sandbox snippets reduce risk and are not a substitute for a reviewed isolation setup.

Data and reuse

The catalog is available as JSON, CSV, taxonomy and snippets. The maps are available too: program, stack, languages, landmarks and world. Everything is also listed and as llms.txt for language models. The schema is documented in the repository under data/SCHEMA.md. Site text and data are released under CC BY 4.0, and the generator code under MIT. Linked resources keep their own licenses.

Corrections

If an entry is wrong, stale or missing, open an issue or pull request on the repository. Include the primary source. Entries are re-checked from time to time and each shows its check date.
