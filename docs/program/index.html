What a program is

A program is one thing seen in eight forms. It is text, then words, then a tree, then something with types, then a running process, then something tested, something proved, and something that keeps changing. Each form is a different answer to the question "what is this?", and each gives a machine a different way to check it.

Follow one small program through all eight. The program is Euclid's algorithm for the greatest common divisor, written about 2,300 years ago and still run every day. On each page you can edit it and watch that form respond, because the figures are driven by a real lexer, parser, type checker, compiler and machine running in your browser.

Why the order matters

Each form is built from the one before, and each is harder to get right. Text that cannot be cut into tokens has no tree. A tree with a type error is never run. A program that runs may fail its tests, and a program that passes its tests may still be wrong for an input nobody tried.

Read the other way, the list is a ladder of checks, from cheapest to strongest: does it parse, does it type-check, does it run, does it pass, is it proved. That ladder is the reason code is the best understood subject for training models. At every rung a machine can say yes or no without asking a person.
