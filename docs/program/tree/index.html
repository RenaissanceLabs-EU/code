Structure: the tree inside the text

Why is 1 + 2 * 3 seven and not nine?

Tokens arrive in a line, but meaning is nested. In 1 + 2 * 3 the multiplication belongs together first, and its result is one side of the sum. A parser turns the line of tokens into a tree that records exactly what belongs to what, following the grammar of the language.

That tree, the abstract syntax tree, is the form in which compilers, formatters and many analysis tools think about code. Compilers translate it, formatters print it back out, editors use it to color and to rename, and analysis tools search it for mistakes.

A grammar is a short list of rules that describes infinitely many programs, because the rules can refer to themselves: an expression may contain an expression, a block may contain a block, to any depth. In most languages a text that does not fit the rules has no tree, and the compiler refuses it. It does not guess what you meant. This strictness is the first deep difference between a programming language and a human one.

Two trees from the same five tokens

1 + 2 * 3 and (1 + 2) * 3 use the same numbers and the same operators. The first is 7 and the second is 9, and the whole difference is the shape of the tree: which operation sits lower, and is therefore done first.

The grammar decides this with precedence (multiplication binds tighter than addition) and associativity (10 - 4 - 3 means (10 - 4) - 3). Parentheses are the programmer's way of overriding both.

What to notice
  • Try 1 + 2 * 3 and then (1 + 2) * 3. The multiplication moves from the bottom of the tree to the top.
  • Leaves are names and numbers. Everything above a leaf is an operation waiting for its parts.
  • Remove a closing bracket. There is no tree at all, only a message saying where the grammar stopped fitting.

Central ideas

Grammar
The set of rules that says which sequences of tokens are programs. Usually a context-free grammar.
Parser
The part of a compiler that builds a tree from tokens according to the grammar.
Abstract syntax tree
The tree of a program with layout and punctuation removed, keeping only structure.
Precedence
The rule for which operator binds tighter when brackets are absent.
Associativity
The rule for grouping a chain of the same operator: left to right, or right to left.
Recursion
A rule that refers to itself. It is what lets a finite grammar describe unlimited nesting.
Syntax error
A place where the text does not fit the grammar. In most languages the program is rejected before anything runs.

Landmarks

  1. 1956
    Hierarchy of grammars Noam Chomsky

    Chomsky's 'Three models for the description of language' (IRE Transactions on Information Theory, 1956) is where the general idea of a hierarchy of grammars was first described; the modern hierarchy with context-free grammars is credited to Chomsky and Schutzenberger's 1963 paper. source

  2. 1960
    Backus-Naur form in ALGOL 60 John Backus (1959 notation), Peter Naur (editor), the ALGOL 60 committee

    Backus presented metalinguistic formulae for the syntax of the international algebraic language at the June 1959 Paris conference, and the 1960 ALGOL 60 report edited by Peter Naur used that notation (with ::= and |) to define a programming language's syntax formally; the year given is the 1960 report. source

  3. 1975
    Yacc Stephen C. Johnson, Bell Labs

    Johnson's Yacc ('Yet Another Compiler-Compiler') was developed at Bell Labs in the early 1970s, appeared in Version 3 Unix, and was fully described in a 1975 technical report. source

  4. 2013
    Tree-sitter Max Brunsfeld

    Tree-sitter's GitHub repository was created in November 2013 with early commits by Max Brunsfeld, and it builds a concrete syntax tree and updates it as the file is edited, fast enough to parse on every keystroke and still useful when the code has syntax errors (talks about it date from 2017 and 2018). source

  5. 2016
    Language Server Protocol Microsoft, Red Hat, and Codenvy (idea from Microsoft's VS Code team)

    On June 27, 2016 Microsoft, Red Hat, and Codenvy announced a collaboration to standardize the Language Server Protocol, a JSON-based protocol that lets one language server serve many editors; the idea grew out of repeated work by the VS Code team after integrating OmniSharp and TypeScript (the year given is this 2016 announcement, not the first internal use). source

Open problems and frontiers

  • Error-tolerant parsing

    Classic panic-mode error recovery often cascades into a chain of errors that drown out the original, and Diekmann and Tratt's CPCT+ (arXiv 2018) reports the complete set of minimum cost repair sequences for LR parsers, so recovery that is cheap, bounded, and gives repairs people trust for arbitrary grammars is still active work. source

  • Making models emit valid syntax

    Grammar-constrained decoding guarantees that a language model's output follows a formal grammar, but most existing methods were limited to specific tasks such as parsing or code generation, and Geng, Josifoski, Peyrard and colleagues (2023) argue it should become a unified framework for structured output. source

  • The cost of running a grammar beside a model

    Executing a context-free grammar over every token of a model's vocabulary at inference time adds non-negligible overhead, which XGrammar (2024) tries to reduce. source

What this means for training models

A model is given text and must produce text, so it has to keep the tree in mind without ever being shown it: every bracket closed, every block ended, every construct complete. Output that does not parse is worth nothing, which makes parsing the cheapest check there is. It needs no tests and takes milliseconds.

Tools use the tree on both sides of training. On the data side, parsers such as tree-sitter pull whole functions out of files, compare code with formatting ignored, and choose gaps that match real syntactic units. On the output side, a grammar can constrain a model as it writes, so that every token it emits keeps the text a valid start of a program in that grammar. Few datasets expose the tree directly, so this layer is thin in the catalog. That thinness is a finding in itself.
