What the world runs on

Most of the rules a modern society follows are no longer carried out by people. A payment clears, a plane holds its course, a dose is measured, a message finds its way across the planet, and at each step the thing doing the work is a program somebody wrote, often long ago. This page collects what can actually be sourced about that, and says where the popular numbers cannot be.

Where code holds things up

Each claim below links to the document it was read from, with the date. Where a field publishes standards instead of statistics, we cite the standard.

The Linux kernel is one program, developed in the open, that thousands of people change every nine weeks or so. Its 7.3 release in October 2026 took in 18,765 non-merge commits from 3,021 developers.

The internet

The internet's core protocols

The internet is defined by public documents called RFCs, and code everywhere implements them. IP, TCP, DNS, BGP and TLS each have a specification anyone can read, and those specifications are still being revised.

  • RFC 791, Internet Protocol, by Jon Postel, is dated September 1981 and is an Internet Standard (STD 5). source, 1981-09
  • RFC 9293, Transmission Control Protocol (TCP), was published in August 2022 as Internet Standard STD 7. It replaced the original TCP specification, RFC 793, and six later documents. source, 2022-08
4 more sourced facts
  • RFC 1035, Domain Names: Implementation and Specification, by Paul Mockapetris, is dated November 1987 and is part of Internet Standard STD 13. source, 1987-11
  • RFC 4271, A Border Gateway Protocol 4 (BGP-4), dated January 2006, specifies the routing protocol used between autonomous systems. source, 2006-01
  • RFC 9846, The Transport Layer Security (TLS) Protocol Version 1.3, was published in July 2026 and obsoletes RFC 8446, the August 2018 specification of TLS 1.3. source, 2026-07
  • The IETF, which produces these documents, has no formal membership. Participants are volunteers, and working groups decide by rough consensus instead of voting. source, 2026-11-24

The web

The web rests on two public specifications, HTTP and HTML, and on the browsers that implement them. HTML has no final version: its specification is a Living Standard that is edited continuously.

  • RFC 9110, HTTP Semantics, was published in June 2022 as Internet Standard STD 97. It defines the parts of HTTP shared by all versions, including the http and https URI schemes. source, 2022-06
  • The HTML specification is published by WHATWG as a Living Standard. On the day it was checked, its header read: Last Updated 24 November 2026. source, 2026-11-24
2 more sourced facts
  • The same document records that in 2019 WHATWG and W3C agreed to work together on a single version of HTML, and that HTML's first years (1990 to 1995) were hosted at CERN and then at the IETF. source, 2026-11-24
  • Chromium describes itself as an open-source browser project, and the Chromium projects as the open-source projects behind the Google Chrome browser. source, 2026-11-24

Government

Mainframes, COBOL and assembly in government

Some of the systems that assess taxes and pay benefits in the United States are decades old and written in COBOL or assembly language. This is documented by the Government Accountability Office, system by system.

  • GAO reported in 2016 that the Treasury's Individual Master File, the authoritative data source for individual taxpayers, was about 56 years old, written in assembly language and running on an IBM mainframe. source, 2016-05-25
  • The same report lists a Department of Veterans Affairs time and attendance system written in COBOL on IBM mainframes, reported as 53 years old, and a Defense system coordinating nuclear forces that still used 8-inch floppy disks. source, 2016-05-25
2 more sourced facts
  • In 2019 GAO examined the ten most critical federal legacy systems and found them to be 8 to 51 years old. It noted that the Department of Education's selected system runs on COBOL. source, 2019-06-11
  • COBOL is still a supported product: IBM sells Enterprise COBOL for z/OS, with version 6.5 documentation current in November 2026, and says it normally ships a fix pack every two months. source, 2026-11-24

Transport

Airborne software

Software on certified aircraft is developed under a specific assurance standard, DO-178C, which the FAA recognizes as an acceptable way to show compliance with airworthiness regulations.

  • FAA Advisory Circular 20-115D, issued July 21, 2017, recognizes RTCA DO-178C, Software Considerations in Airborne Systems and Equipment Certification (dated December 13, 2011), and its European twin EUROCAE ED-12C. source, 2017-07-21
  • The circular describes this as an acceptable means, but not the only means, of showing compliance for the software aspects of airborne systems and equipment. It also recognizes supplements for tool qualification (DO-330), model-based development (DO-331), object-oriented technology (DO-332) and formal methods (DO-333). source, 2017-07-21

Spaceflight software

The code that flew Apollo 11 is public and readable today, and current missions run on software that NASA publishes as open source or describes in detail.

  • The Apollo 11 guidance computer source code for the Command Module (Comanche055) and the Lunar Module (Luminary099) is public domain and online, digitized by Virtual AGC and the MIT Museum. The listings are dated April 1 and July 14, 1969 and are assembled with the yaYUL assembler. source, 2026-11-24
  • NASA's Ingenuity Mars helicopter, which first flew on April 19, 2021, used F Prime, a flight software framework created at the Jet Propulsion Laboratory in 2013 and released as open source in 2017. source, 2021-07-08
2 more sourced facts

  • The onboard scripts that run observations on the James Webb Space Telescope are written in JavaScript, according to the Space Telescope Science Institute. They let the telescope skip a visit or stop commanding an instrument on its own when something goes wrong. source, 2020

OpenSSL and encrypted connections

OpenSSL is an open source toolkit that implements TLS, the protocol used to encrypt connections on the internet. One missing bounds check in it, found in 2014, exposed the memory of servers around the world.

  • The project describes OpenSSL as a robust, commercial-grade, full-featured open source toolkit for the TLS (formerly SSL), DTLS and QUIC protocols. source, 2026-11-24
  • The Heartbleed site, written by the team that co-discovered the bug, noted that Apache and nginx, the two best known web servers using OpenSSL, had a combined share of over 66% of active sites in Netcraft's April 2014 survey. source, 2014-04

Verified software

Proved software in production

A few programs in real use come with machine-checked mathematical proofs that the code does what its specification says. The seL4 microkernel and the CompCert C compiler are the best known.

  • seL4 has machine-checked proofs, written in Isabelle/HOL, for Arm, RISC-V and Intel architectures: functional correctness of the C code against its specification and, in supporting configurations, correctness of the binary and the security properties integrity, availability and confidentiality. source, 2026-11-24
  • The seL4 Foundation lists products built on seL4, including the SkyOS-M operating system in NIO's mass-produced ONVO L60 electric car and a voice communication system used by air traffic and maritime controllers. source, 2026-11-24
2 more sourced facts
  • CompCert is a compiler for almost all of ISO C 2011 with a machine-checked proof that the generated code behaves as the source program does. Its proofs are developed in Rocq, it targets ARM, PowerPC, RISC-V and x86, and it is aimed at critical embedded software. source, 2026-11-24
  • CompCert was qualified for the MFC_NG flight computer of ATR 42/72 aircraft, which the project describes as the first time certification credits under DO-178C, DO-333 and DO-330 could be claimed from the use of a compiler. source, 2026-11-24

When code fails

Because programs act without anyone watching, their mistakes act too. These are well documented cases, each from the official report or the maintainers' own account. They are worth knowing for the same reason engineers study bridge collapses.

  1. 1985
    Therac-25 radiation overdoses

    Between June 1985 and January 1987, a computer-controlled radiation therapy machine gave six known patients massive overdoses, causing deaths and serious injuries. One fault was a race condition: if the operator edited the treatment settings and returned to the command line within about 8 seconds, the software never noticed the edit. Earlier machines had hardware interlocks that masked the same kind of error; the Therac-25 relied on software for those safety functions.

    Software that replaces a physical safety mechanism has to be engineered and checked as a safety mechanism, and reused code is not safe just because it ran before. source

  2. 1996
    Ariane 5 flight 501

    On June 4, 1996, about 37 seconds after main engine ignition, software in both inertial reference systems tried to convert a 64-bit floating point number into a 16-bit signed integer. The value was too large, the unprotected Ada conversion raised an error, and both units shut down. The rocket lost its guidance data, veered off course, broke up and destroyed itself on its maiden flight. The code that failed was an alignment routine kept from Ariane 4 that had no purpose after lift-off.

    Code that was correct for one machine carries its assumptions with it, and they have to be checked again when it is reused. source

  3. 1999
    Mars Climate Orbiter

    A ground software file called Small Forces reported thruster impulse in English units (pound-force seconds) where the specification required metric units (newton seconds), a factor of 4.45. Over the nine-month cruise the small errors accumulated in the trajectory estimate, and on September 23, 1999 the spacecraft reached Mars about 170 kilometers lower than planned. It was destroyed in the atmosphere or passed back into space, and was lost.

    The interface between two programs is part of the program, including the units of every number that crosses it. source

  4. 2000
    The Year 2000 remediation

    Many programs stored years as two digits, so the year 2000 could be read as 1900. Instead of a disaster this became a very large repair job: the United States Senate's special committee reported that the country spent an estimated 100 billion dollars on the problem, 8.5 billion of it in the federal government. The committee's final report, dated February 29, 2000, is titled Y2K Aftermath: Crisis Averted.

    A shortcut in a data format can outlive its authors by decades, and maintenance done in time looks afterward as if nothing happened. source

  5. 2012
    Knight Capital

    On August 1, 2012, a trading firm's automated order router ran a defective function that had been left in its code since 2005, after new code was deployed incorrectly in late July. In the first 45 minutes of trading it sent more than 4 million orders while trying to fill 212 customer orders and traded more than 397 million shares. The firm lost more than 460 million dollars and later paid a 12 million dollar penalty to the SEC.

    Dead code that stays in a system is still code, and a deployment is part of the program's correctness. source

  6. 2014
    Heartbleed

    A missing bounds check in OpenSSL's implementation of the TLS heartbeat extension let anyone on the internet read up to 64 kilobytes of a server's or client's memory per request, which could include secret keys and passwords. The bug shipped in OpenSSL 1.0.1 in March 2012 and was fixed in version 1.0.1g on April 7, 2014. It was found by Neel Mehta of Google Security and, independently, by a team at Codenomicon.

    A library that almost everyone depends on can go years with a simple flaw in it when few people are looking. source

  7. 2016
    The left-pad incident

    On March 22, 2016, after a dispute over a package name, a developer removed 273 of his packages from the npm registry, among them a tiny one called left-pad. Many thousands of projects depended on it directly or through other packages, and npm saw hundreds of failed installs per minute. Within ten minutes another developer published a functionally identical replacement.

    A program depends on everything its dependencies depend on, and on those things staying published. source

  8. 2021
    Log4Shell

    Log4j, a Java logging library embedded in thousands of other software packages, would follow lookups placed inside logged text, so an attacker who could get a string logged could make the server load and run code from a remote address. The feature had been added in 2013; the flaw was reported to Apache on November 24, 2021, became public on December 9, and was rated 10.0, the maximum severity. The United States Cyber Safety Review Board called it an endemic vulnerability that will remain in systems for perhaps a decade or longer.

    A convenience feature in a widely embedded library can become an entry point into every system that includes it, and removing it everywhere takes years. source

  9. 2024
    The xz utils backdoor

    On March 29, 2024, engineer Andres Freund reported that the release archives of the compression tool xz, versions 5.6.0 and 5.6.1, contained a deliberately hidden backdoor, part of it present only in the distributed archives and not in the source repository. He found it while investigating why ssh logins on a Debian test system were using a lot of processor time. The versions had not yet been widely adopted, mostly reaching pre-release distributions; the issue is tracked as CVE-2024-3094.

    A widely used component maintained by very few people is a target, and what gets shipped has to be checkable against the source. source

  10. 2024
    The CrowdStrike outage

    On July 19, 2024, a security vendor delivered a content update whose new template expected 21 input fields, while the sensor code on each Windows machine supplied only 20. With no runtime bounds check, reading the 21st value went past the end of the array in the sensor's Content Interpreter and crashed the system. Microsoft estimated that 8.5 million Windows devices were affected, less than one percent of all Windows machines.

    Data that steers privileged code is effectively code, and it needs the same validation, testing and staged rollout. source

Why code is never finished

A bridge, once built, stays built. Software sits on other software that keeps moving, so a program left alone slowly stops working. Keeping it alive is most of the work.

Versions

Software is released again and again, and each release gets a number that tells users what changed. Semantic Versioning is a published convention for those numbers: a version is MAJOR.MINOR.PATCH, and which part increases says whether upgrading can break you.

  • Semantic Versioning 2.0.0: increment MAJOR for incompatible API changes, MINOR for functionality added in a backward compatible manner, PATCH for backward compatible bug fixes. The specification was originally written by Tom Preston-Werner. source, 2026-11-24
  • The Linux kernel showed two live lines on the same day: stable release 7.3.6 and mainline candidate 7.4-rc4. source, 2026-11-24

Dependencies and supply chains

Almost no program is written from nothing. It pulls in packages, which pull in other packages, and the result is a tree of code written by people the author has never met. That tree is the program's supply chain, and it can break or be attacked at any link.

  • A 2019 study of the npm ecosystem (data through April 2018) found that installing an average npm package means implicitly trusting 79 third-party packages and 39 maintainers. source, 2019-08
  • In March 2016 the removal of one small package, left-pad, caused hundreds of failed installs per minute across the npm registry. source, 2016-03
1 more sourced facts
  • In March 2024 a backdoor was found in release archives of xz, a compression tool that many systems include indirectly. source, 2024-03-29

Maintenance

A program in use keeps needing work: fixing faults, adapting to new hardware, laws and neighboring systems, and keeping it running. There is no single agreed percentage for this, so none is given here, but one well documented budget shows the shape of it.

  • The United States federal government spent about 75 percent of its total information technology budget for fiscal year 2015 on operations and maintenance, and 5,233 of its roughly 7,000 IT investments spent all of their funds that way. source, 2016-05-25
  • The Cyber Safety Review Board expects vulnerable copies of Log4j to remain in systems for many years, perhaps a decade or longer, after the fix was published. source, 2022-07-11

Version control

Code is kept as a history of changes, not as a pile of files. Each change records who made it, when and why, and any earlier state can be recovered. The tool almost everyone uses for this, Git, was written for the Linux kernel.

  • The Linux kernel project used the proprietary system BitKeeper from 2002. When its free-of-charge status was revoked in 2005, the kernel community, and in particular Linus Torvalds, built Git, aiming for speed, a simple design, strong support for thousands of parallel branches, full distribution and efficient handling of projects as large as the kernel. source, 2026-11-24
  • GitHub, a hosting service built on Git, reported 630 million repositories in its 2025 Octoverse report. source, 2025-10-28

Code review

In most serious projects a change is read by someone other than its author before it is accepted. Review catches faults, spreads knowledge of the code and leaves a record of who vouched for what.

  • In the Linux kernel, a Reviewed-by tag is a statement of opinion that the patch is an appropriate modification of the kernel, given by someone who has carried out a technical review of it. A Signed-off-by tag certifies that the submitter has the right to contribute the code. source, 2026-11-24
  • A 2018 study of code review at Google analyzed 9 million reviewed changes and found that the median developer authors about 3 changes a week and that the median time for the entire review process is under 4 hours. source, 2018

Long-lived code

Working code tends to stay. Systems written half a century ago were still in daily service when last reported, and numerical libraries from earlier decades are still being released. Old code stays because it is in use.

  • In 2016 the United States Treasury's Individual Master File, which assesses taxes and generates refunds for individual taxpayers, was reported as about 56 years old and written in assembly language. source, 2016-05-25
  • The Apollo 11 guidance computer listings from 1969 are public, and the repository points to the Virtual AGC project for anyone who wants to compile them. source, 2026-11-24
1 more sourced facts
  • LAPACK, written in Fortran 90, is still provided by four institutions and stood at version 3.12.1 in November 2026. source, 2026-11-24

Bit rot and changing foundations

A program that is never touched still stops working, because everything under it keeps changing: languages, libraries, operating systems and protocols. Keeping software alive means moving with them.

  • Python 2 was retired on January 1, 2020. Work on Python 3.0 began in 2006, and the retirement date, first announced in 2008 as 2015, was extended to 2020 in 2014 because so much code had not moved. source, 2026-11-24
  • Even core internet standards are replaced: the 2018 specification of TLS 1.3, RFC 8446, was obsoleted by RFC 9846 in July 2026, and in 2022 RFC 9293 replaced the original TCP specification. source, 2026-07
1 more sourced facts
  • The HTML specification is a Living Standard with no final version; its header showed an update on the day it was checked. source, 2026-11-24

Reproducible builds

People read source code, but machines run binaries, and the step between them is usually taken on trust. A build is reproducible when others can rebuild the same source and check that they get the same result, which makes tampering in between detectable.

  • The Reproducible Builds project defines reproducible builds as a set of software development practices that create an independently verifiable path from source to binary code. source, 2026-11-24
  • The xz backdoor of 2024 was partly present only in the distributed release archives and not in the source repository, which is the gap this practice is meant to close. source, 2024-03-29

Preserving source code

Source code is a record of how things work, and it disappears when hosting sites close or projects are deleted. Software Heritage collects and preserves software in source code form.

  • Software Heritage states its mission as preserving software source code for present and future generations. source, 2026-11-24
  • On November 24, 2026 the archive's public counters showed 31,512,603,597 unique source files, 6,446,026,817 commits and 463,285,723 project origins. source, 2026-11-24

What this means for training models

Three things follow for anyone teaching a model to write code. Most real code is old, large and written in languages that benchmarks barely touch. The cost of a mistake is set by where the code runs, not by how hard it was to write. And the dominant activity is maintenance: reading and changing what exists. The change page and the languages map show how far current open training material is from that picture.
