This is a worked example you can run. It takes a body of source code, reviews its licenses, cleans it, removes duplicates and secrets, splits it without leaking related files across splits, checks it against evaluation problems, and writes a versioned dataset with a card, ready to upload to the Hugging Face Hub. Every number on this page comes from one real run on 2026-11-25. The core pipeline uses only Python 3.9's standard library, needs no network, runs in about 20 seconds in under 50 MB of memory, and on the same Python tree with the settings in run_all.sh produces byte-identical output when you run it again.

The corpus is the CPython 3.9.6 standard library, because it is already on your machine and its main license is clear (PSF License Version 2, read from the license file next to the source), though a few files carry other notices, which the license step handles. It is small and it is Python only. The steps are the ones you would follow for a real corpus of many repositories, and the page says where a real project needs more.

Get the codeEverything lives in examples/build-dataset in the site's repository: eight numbered scripts, a test suite of 15 tests, a run log with every count, and the generated dataset card.

0. Two different things: a catalog and a dataset

People often mix these up, and the difference decides what you may publish.

Publishing a catalog of resource metadataRedistributing training examples
What you publishFacts about resources: names, links, sizes, stated licenses, short descriptions in your own words.The examples themselves: copies of files, or records that contain their text.
Which licenses applyIn general, none of the code licenses, because you are not copying the code (local law may add database or other rights). You must still report each license correctly and link to the original.The license of every file. Copies are copies of the source, and derived records usually count as derivative works.
What you must doKeep the entry accurate and dated. Do not copy a card's text word for word.Keep license texts and copyright notices, summarize changes, meet attribution terms (MIT, BSD, Apache-2.0), respect copyleft terms where files carry them, and keep a per-file license field.
This site's catalogIs this kind. It links to datasets and does not host them.The example on this page is this kind, which is why it ships the license file and records the license on every record.

A dataset you compile can have its own terms for the compilation, but it cannot relicense the parts. That is why the card below sets license: other and carries a license field per file. Gated datasets such as The Stack add access terms on top of the file licenses, and those terms belong to the publisher, not to the code authors. This is general information, not legal advice. For a dataset of third-party code, have the license review checked by someone qualified.

Which materials can be combined and republished? Files under permissive licenses (MIT, BSD, Apache-2.0, PSF-2.0, 0BSD) can be combined and republished if you meet each license's terms: keep the license text and notices, and where required (Apache-2.0, PSF-2.0) say what you changed. 0BSD asks for nothing. Mixing in files under copyleft licenses (GPL family, LGPL, MPL, EPL) brings those terms along, The Stack v1.1 excluded MPL, EPL and LGPL code, which its card calls weak copyleft. Synthetic examples also have terms: check the dataset's own license and the terms of the model that wrote them, since they can differ. A benchmark's problems may be used for evaluation under its terms, and should stay out of the training set in any case.

1. Pick sources and record provenance

Provenance is what lets you answer questions later: where did this file come from, under what license, which version, and can I remove it if its author asks? Record it per file at the moment you collect, not afterwards.

01_collect.py: detect a per-file license header
HEADER_PATTERNS = [
    ("Apache-2.0", re.compile(r"licen[sc]ed under the apache license,? version 2\.0|also licen[sc]ed under the apache license, 2\.0")),
    ("MIT", re.compile(r"licen[sc]ed under the mit license|permission is hereby granted, free of charge")),
    ("LicenseRef-HPND-style", re.compile(r"permission to use, copy, modify,? and distribute this software")),
    ("LicenseRef-BSD-style", re.compile(r"redistribution and use in source and binary forms")),
]


def detect_header_license(text):
    head = text[:6000].lower()
    found = [name for name, rx in HEADER_PATTERNS if rx.search(head)]
    if not found:
        return None
    if "MIT" in found and "Apache-2.0" in found:
        return "MIT OR Apache-2.0"
    return found[0]

2. Review licenses

The pipeline uses an allow-list of SPDX license identifiers and refuses anything it cannot map to one. In this run 14 files carried their own third-party notices that matched permissive-style wording but not a known identifier, so they were dropped until a person reviews them. A header regex is a first pass, not a legal review.

allowed_licenses.json
{

  • Keep the license on every record, and ship the license text with the dataset.
  • Keep enough provenance (path, source version, hash) to honor a removal request, and version the dataset so a removal produces a new tagged release.
  • For third-party repositories, publish an opt-out channel on the card. The example has none, because its source is the Python standard library, which the PSF publishes.

3. Filter

Filters remove files that teach nothing or teach the wrong thing: tiny stubs, generated code, minified blobs, data tables disguised as code. Each rule is simple, and the run prints how many files each one removed so you can see whether a rule is too strict.

02_filter.py: the rules
import common

MIN_BYTES = 150
MAX_LINES = 5000
MAX_LINE_LEN = 1000
MAX_AVG_LINE_LEN = 100
MIN_ALNUM_FRAC = 0.25
AUTOGEN_RE = re.compile(r"auto[- ]?generated|do not edit|generated by|this file was generated", re.I)

RULES = ["min_size", "max_lines", "max_line_length", "avg_line_length", "alnum_fraction", "autogenerated_header"]


def rule_hits(text, size):
    lines = text.split("\n")
    longest = max((len(l) for l in lines), default=0)
    avg = sum(len(l) for l in lines) / max(len(lines), 1)
    alnum = sum(c.isalnum() for c in text) / max(len(text), 1)
    head = "\n".join(lines[:5])
    return {
        "min_size": size < MIN_BYTES,
        "max_lines": len(lines) > MAX_LINES,
        "max_line_length": longest > MAX_LINE_LEN,
        "avg_line_length": avg > MAX_AVG_LINE_LEN,
        "alnum_fraction": alnum < MIN_ALNUM_FRAC,
        "autogenerated_header": bool(AUTOGEN_RE.search(head)),
    }


def license_allowed(expr, allowed):
    """SPDX-style: 'A OR B' passes if any side is on the allow-list."""
    return any(part.strip() in allowed for part in expr.split(" OR "))

Result: of 674 readable files, 24 were too small and 3 had an auto-generated header. No file hit the line-length rules, which is what you would expect from hand-written standard library code. In a web-scale corpus these rules remove far more. Read a sample of what each rule removes before you trust it.

4. Remove secrets and personal data

Source code contains keys, passwords, email addresses and addresses of private machines. The scrubber replaces them with placeholders and logs only the rule and the position, never the matched text.

03_scrub.py: the patterns
PRIVATE_KEY_RE = re.compile(r"-----BEGIN [A-Z0-9 ]*PRIVATE KEY(?: BLOCK)?-----.*?-----END [A-Z0-9 ]*PRIVATE KEY(?: BLOCK)?-----", re.S)
AWS_RE = re.compile(r"\bAKIA[0-9A-Z]{16}\b")
GITHUB_RE = re.compile(r"\bgh[pousr]_[A-Za-z0-9]{36,}\b")
PASSWORD_RE = re.compile(r"""(?i)([\w.]*(?:password|passwd|pwd|secret|api_key)\w*)(\s*=\s*)(["'])([^"'\n]{4,})\3""")
EMAIL_RE = re.compile(r"[A-Za-z0-9._%+-]+@[A-Za-z0-9-]+(?:\.[A-Za-z0-9-]+)*\.[A-Za-z]{2,}")
IPV4_RE = re.compile(r"(?<![\d.])(?:(?:25[0-5]|2[0-4]\d|1\d\d|[1-9]?\d)\.){3}(?:25[0-5]|2[0-4]\d|1\d\d|[1-9]?\d)(?![\d.])")

Replacements in this run: 163 email addresses in 119 files, 10 globally routable IPv4 addresses and 1 password-like literal (an example in a docstring). There were no keys or tokens. Loopback, private and documentation addresses were kept on purpose, because they are not personal data and replacing them breaks code examples. After scrubbing, every file that parsed before still parses.

A pattern scrubber has hard limits. It cannot find secrets with no fixed format, such as a random password in a config file, or names and other personal data in prose and comments, or usernames in file paths. It also produces false positives, such as the addresses of authors in headers. For a real dataset use a stronger tool as well and review a sample by hand: the BigCode PII pipeline, detect-secrets or gitleaks.

5. Deduplicate

Real code is full of copies: vendored libraries, forks, boilerplate. Duplicates inflate benchmark results and waste training tokens, and a test file that is a near-copy of a training file measures memory. First remove exact duplicates by content hash. Then remove near-duplicates: split each file into overlapping runs of five tokens, summarize the set with a MinHash signature, find candidate pairs with locality-sensitive hashing, and confirm each pair with the exact Jaccard similarity.

04_dedup.py: MinHash and LSH, standard library only
SEED = 1337
NUM_PERM = 64
BANDS = 16          # 16 bands x 4 rows: P(candidate | J=0.8) = 1-(1-0.8**4)**16 > 0.999
ROWS = NUM_PERM // BANDS
SHINGLE = 5
THRESHOLD = 0.8
PRIME = (1 << 61) - 1
MASK64 = (1 << 64) - 1


def shingle_hashes(text):
    toks = common.tokens(text)
    if len(toks) < SHINGLE:
        toks = toks + [""] * (SHINGLE - len(toks))
    return {int.from_bytes(hashlib.blake2b(" ".join(toks[i:i + SHINGLE]).encode("utf-8"), digest_size=8).digest(), "big")
            for i in range(len(toks) - SHINGLE + 1)}


def make_perms(seed=SEED, n=NUM_PERM):
    rng = random.Random(seed)
    return [(rng.randrange(1, PRIME), rng.randrange(0, PRIME)) for _ in range(n)]


def minhash(hashes, perms):
    return tuple(min((a * h + b) % PRIME for h in hashes) for a, b in perms)


def jaccard(a, b):
    return len(a & b) / len(a | b) if (a or b) else 1.0


def lsh_candidates(sigs):
    """sigs: {key: signature}. Returns sorted candidate pairs (key_a < key_b) sharing any band bucket."""
    pairs = set()
    for band in range(BANDS):
        buckets = {}
        for key in sorted(sigs):
            buckets.setdefault(sigs[key][band * ROWS:(band + 1) * ROWS], []).append(key)
        for members in buckets.values():
            for i in range(len(members)):
                for j in range(i + 1, len(members)):
                    pairs.add((members[i], members[j]))
    return sorted(pairs)

Result: no exact duplicates, and 44 near-duplicates in 16 clusters, every one of them a codec module under encodings/ that shares boilerplate (similarity 0.80 to 0.98). For a large corpus, use a tested implementation: datatrove and the BigCode near_deduplication code do the same thing at scale.

6. Split without leaking, and check for contamination

If you split at random by file, near-identical files from one project land in both training and test data, and the test score measures memory. Split by group instead: all files of a repository go to the same split. Here the group is the top-level package, which stands in for a repository, and the split is a stable hash of the group name, so it does not change when you add data.

05_split.py: group split
def group_of(path):
    """Top-level package directory, or the module name for a top-level file. Stands in for a repository."""
    first = path.split("/")[0]
    return first[:-3] if first.endswith(".py") else first


def split_of(group, salt=SALT):
    b = int(hashlib.sha256((salt + ":" + group).encode("utf-8")).hexdigest(), 16) % 100
    for name, rng in BUCKETS.items():
        if b in rng:
            return name


def check_no_group_overlap(records):
    """Return (ok, offending_groups). A group is offending if it appears in more than one split."""
    seen = {}
    for r in records:
        seen.setdefault(r["repo"], set()).add(r["split"])
    bad = sorted(g for g, s in seen.items() if len(s) > 1)
    return (not bad), bad

Result: 524 files for training (523 after the decontamination step below), 16 for validation and 49 for test, with 0 groups in more than one split (the run asserts it and writes the proof to split_check.json). The validation set is small because the hash assigns whole packages, which is the price of a clean split on a small corpus. Related repositories (forks, mirrors, a library and its copies in other projects) also leak: group them under one name before you split.

Contamination is a separate problem: a training file may contain a benchmark problem or its solution. The decontamination script removes any training file that shares a 13-token sequence with an evaluation file. To show that it works, the example plants a problem that reuses the body of one standard library function. The run found 220 overlapping sequences, removed that file from training, and left the two clean probe problems alone.

decontaminate.py: n-gram overlap
N = 13
SKIP_FIELDS = {"id", "note"}


def ngrams(toks, n=N):
    return zip(*[toks[i:] for i in range(n)])


def eval_index(eval_path, n=N):
    """{13-gram tuple: eval id of the first record that contains it}"""
    idx = {}
    for rec in common.read_jsonl(eval_path):
        text = "\n".join(str(v) for k, v in sorted(rec.items()) if k not in SKIP_FIELDS and isinstance(v, str))
        for g in ngrams(common.tokens(text), n):
            idx.setdefault(g, rec["id"])
    return idx


def overlap(text, idx, n=N):
    """Return (count of overlapping 13-grams, sorted eval ids matched, example gram as a string or None)."""
    hits = 0
    ids = set()
    example = None
    for g in ngrams(common.tokens(text), n):
        if g in idx:
            hits += 1
            ids.add(idx[g])
            if example is None:
                example = " ".join(g)
    return hits, sorted(ids), example

In real use, pass the actual benchmark files for every benchmark you will report on. N-gram matching misses paraphrased copies, so keep a private held-out set as well. Removing the whole file is blunt; cutting out the function is a reasonable refinement.

8. Write the dataset card

The card is the dataset repository's README.md. Hugging Face reads its YAML header to set the license, languages, tasks and the configurations that say which file is which split. The body should state, with numbers from the run, where the data came from, what was removed, how it was split, what is in each field, and what it is not good for. The card in the example is generated by a script from the run's own logs, so the numbers cannot drift from the data.

9. Version and publish

Publish privately first, read the rendered card, then make the repository public. Tag every release so that experiments can pin the exact data they used, and record the tag in each training run.

Where a real project goes beyond this

  • More sources and languages. Add a collection step for repositories and a language detector, and keep a repository field distinct from the license.
  • A stronger license step. Use a license scanner such as ScanCode, and get a person to review anything unmapped.
  • Stronger secret and personal-data removal. Add a purpose-built tool and review a sample by hand.
  • Scale. Move deduplication and filtering to a framework such as datatrove, and stream instead of loading files in memory.
