How the open code models were trained

18 open code models and what their own reports and model cards say about how they were made: the data, the stages, the reward. Compare them side by side, then take the parts that fit.

Patterns

What the recipes have in common

FIM is standard in code pretraining

Seven of the reports describe fill-in-the-middle training. StarCoder2 applies it to 50% of repositories and then to each file chunk with 50% probability, DeepSeek-Coder and DeepSeek-Coder-V2 (16B only) use a 0.5 rate, Code Llama uses 0.9, and Seed-Coder uses 0.5 in regular pretraining and 0.1 in continued pretraining.

Seen in: StarCoder2 (3B, 7B, 15B), Code Llama (7B, 13B, 34B, 70B; Base, Python, Instruct), DeepSeek-Coder (1.3B to 33B), DeepSeek-Coder-V2 (Lite 16B and 236B), Seed-Coder (8B Base, Instruct, Reasoning), Granite Code (3B, 8B, 20B, 34B), Olmo 3 (7B and 32B; Base, Think, Instruct)

Context is extended in a short stage after the base run

Code Llama, DeepSeek-Coder, StarCoder2, Qwen2.5-Coder and SmolLM3 grow context in a separate stage that uses a small share of the budget, for example StarCoder2's 200B tokens at 16,384 or SmolLM3's two 50B-token stages to 32k and 64k. DeepSeek-Coder-V2 reaches 128K in two steps of 1000 training steps each, at 32K and then 128K.

Seen in: Code Llama (7B, 13B, 34B, 70B; Base, Python, Instruct), DeepSeek-Coder (1.3B to 33B), DeepSeek-Coder-V2 (Lite 16B and 236B), StarCoder2 (3B, 7B, 15B), Qwen2.5-Coder (0.5B to 32B), SmolLM3-3B

Many recipes start from an existing model

Code Llama (500B tokens on Llama 2), DeepSeek-Coder-V2 (6T tokens from a DeepSeek-V2 checkpoint), Qwen2.5-Coder (5.5T tokens on Qwen2.5) and Kimi-Dev (about 150B mid-training tokens on Qwen2.5-72B-Base) all continue from earlier weights. Only Code Llama reports the comparison: an identical 7B model trained from scratch on the same data needed about 240B more tokens to match its loss.

Seen in: Code Llama (7B, 13B, 34B, 70B; Base, Python, Instruct), DeepSeek-Coder-V2 (Lite 16B and 236B), Qwen2.5-Coder (0.5B to 32B), Kimi-Dev-72B

Synthetic data is kept only if it executes

Code Llama keeps the first of ten sampled solutions that passes generated unit tests, Qwen2.5-Coder keeps synthetic pretraining code only if an executor ran it, Seed-Coder and OpenCoder verify synthetic instruction data in a sandbox or with test cases, and Olmo 3 keeps (problem, solution, tests) triplets whose solutions pass more than 80% of tests. OpenCodeReasoning is the counterexample: it found execution filtering lowered benchmark accuracy and preferred instruction diversity.

Seen in: Code Llama (7B, 13B, 34B, 70B; Base, Python, Instruct), Qwen2.5-Coder (0.5B to 32B), Seed-Coder (8B Base, Instruct, Reasoning), OpenCoder (1.5B and 8B), Olmo 3 (7B and 32B; Base, Think, Instruct), OpenCodeReasoning-Nemotron (7B, 14B, 32B)

RL rewards for code are binary pass or fail on tests

DeepCoder, AceReason-Nemotron, Skywork-OR1, DeepSWE-Preview and Kimi-Dev all use a 0 or 1 outcome reward, and DeepCoder says it avoids K-of-N partial credit because it can lead to reward hacking. AceReason and DeepCoder reward code only if it passes all tests, and Kimi-Dev requires the patch to pass all ground-truth unit tests.

Seen in: DeepCoder-14B-Preview, AceReason-Nemotron (7B and 14B), Skywork-OR1 (7B and 32B), DeepSWE-Preview, Kimi-Dev-72B

RL prompts are filtered to a difficulty band

Skywork-OR1 removes prompts the base model always or never solves, AceReason scores difficulty with DeepSeek-R1-671B and drops unsolved problems, Kimi-Dev discards prompts with pass@16 of 0 and re-adds them later, and Seed-Coder's reasoning run filters problems with correctness above 87.5%. Skywork-OR1 and Kimi-Dev state that zero-advantage groups and prompts with pass@16 of 0 do not contribute to the loss.

Seen in: Skywork-OR1 (7B and 32B), AceReason-Nemotron (7B and 14B), Kimi-Dev-72B, Seed-Coder (8B Base, Instruct, Reasoning)

Reasoning RL drops the KL term and grows context in stages

DeepCoder, DeepSWE, Seed-Coder, Skywork-OR1 and AceReason remove or zero the KL loss, and DeepCoder, DeepSWE and Seed-Coder also use DAPO-style changes such as clip high or overlong filtering. AceReason extends response length from 8K to 32K in stages, Skywork-OR1 uses multi-stage context growth, and DeepCoder lengthens from 16K to 32K.

Seen in: DeepCoder-14B-Preview, DeepSWE-Preview, Seed-Coder (8B Base, Instruct, Reasoning), Skywork-OR1 (7B and 32B), AceReason-Nemotron (7B and 14B)

A late phase of higher-quality data closes pretraining

Granite Code ends with 500B tokens of 80% code and 20% language data after 3T to 4T code-only tokens, OpenCoder anneals on 100B tokens that include synthetic code textbooks and algorithmic data, and SmolLM3 raises code from 12% to 24% in its last decay phase. Seed-Coder and Olmo 3 likewise switch to high-quality and task data in continued pretraining and midtraining.

Seen in: Granite Code (3B, 8B, 20B, 34B), OpenCoder (1.5B and 8B), SmolLM3-3B, Seed-Coder (8B Base, Instruct, Reasoning), Olmo 3 (7B and 32B; Base, Think, Instruct)

Allen Institute for AI (Ai2)2025-11

Olmo 3 (7B and 32B; Base, Think, Instruct)

7B and 32B parameters, denseweights, data and codeIn the catalog

no earlier checkpoint named in the report

Reusable idea Build RL code data by generating (problem, solution, tests) triplets, executing the tests, and keeping only examples whose solutions pass more than 80% of them.

Read the full recipe
Pretraining
Up to 5.9T tokens of pretraining (Dolma 3 Mix, called 6T), 100B tokens of midtraining, and 50B (7B) or 100B (32B) tokens of long-context extension. Dolma 3 Mix: web pages, olmOCR science PDFs, Stack-Edu GitHub code, arXiv, FineMath; midtraining adds Stack-Edu (FIM) and CraneCode. Code share: Stack-Edu (rebalanced) is 409B tokens, 6.89% of the 6T pretraining mix. Midtraining uses a Stack-Edu variant in which 50% of documents get a fill-in-the-middle transform (StarCoder2 procedure), plus 18.8B tokens of rewritten Python (CraneCode). Long-context extension supports up to 65K context.
Supervised
Think SFT code prompts come from AceCoder, The Algorithms (Python), Llama Nemotron post-training and OpenCodeReasoning, with up to 16 responses per prompt kept only if they pass synthetic test cases, plus OpenThoughts 3 code. Teacher: QwQ-32B (responses); GPT-4.1 (test cases).
RL or preference
DPO with delta-learning pairs, then OlmoRL (GRPO with DAPO and Dr GRPO changes). Reward: Code: a test-case verifier, tried as percent of tests passed and as all-or-nothing. Tasks: Code prompts from AceCoder, Klear-Reasoner Code, Nemotron Post-training Code, SYNTHETIC-2 and OpenCodeReasoner; synthetic (problem, solution, tests) triplets kept if solutions pass more than 80% of tests. DPO pairs use Qwen 3 32B (thinking) as chosen and Qwen 3 0.6B (thinking) as rejected. Code execution for rewards runs on AWS Lambda.
Result
The report states Olmo 3 Base 32B achieves double-digit improvements on Math and Code composites over the other fully-open 32B models (report v2, April 2026).

Agentica and Together AI2025-07

DeepSWE-Preview

32B parameters, denseweights, data and codeIn the catalog

fine-tuned from Qwen3-32B

Reusable idea Mask the loss on trajectories that hit max context, max steps or a timeout (compact filtering), so reward is assigned only when the agent deliberately submits.

Read the full recipe
RL or preference
GRPO++ (clip high, no KL loss, no reward standard deviation, length normalization, leave-one-out advantage, compact filtering, no entropy loss), extended to multi-turn by masking environment observations. Reward: Sparse outcome: 1 if the patch passes the selected Pass2Pass and Fail2Pass tests within 5 minutes, 0 otherwise. Tasks: About 4.5K R2E-Gym problems, with repositories shared with SWE-Bench Verified removed; six days on 64 H100 GPUs. Compact filtering masks trajectories that hit max context, max steps or timeout, which the blog says delays reward collapse. No SFT or distillation stage is used.
Result
The blog states 42.2% Pass@1 on SWE-Bench-Verified (averaged over 16 runs) and 59% with hybrid test-time scaling (blog of July 2025).

Alibaba Qwen2025-07

Qwen3-Coder (480B-A35B-Instruct announced first)

480B total with 35B active (mixture of experts)weightsIn the catalog

Reusable idea Scale code RL by automatically generating test cases for many kinds of real-world coding tasks, choosing tasks that are hard to solve and easy to verify.

Read the full recipe
Pretraining
7.5T tokens. Not itemized in the blog; Qwen2.5-Coder was used to clean and rewrite noisy data. Code share: 70% code ratio. The model natively supports 256K context and extends to 1M with YaRN, and the blog says it is optimized for repo-scale and pull request data.
RL or preference
Reward: Execution-driven: test cases are scaled automatically for diverse coding tasks; agent RL gets feedback from running environments. Tasks: A broader set of real-world coding tasks than competitive programming; long-horizon agent RL on SWE-Bench-style tasks across 20,000 independent environments in parallel. The blog states code RL improved code execution success rates and also helped other tasks, and calls the target 'hard to solve, easy to verify'. Algorithm names are not given.
Result
The blog states Qwen3-Coder achieves state-of-the-art performance among open-source models on SWE-Bench Verified without test-time scaling (blog of July 22, 2025).

Hugging Face2025-07

SmolLM3-3B

3B parameters, denseweights, data and codeIn the catalog

no earlier checkpoint named in the blog

Reusable idea Merge the aligned model soup with a mid-training checkpoint (0.9 and 0.1) to recover long-context performance lost during reasoning mid-training.

Read the full recipe
Pretraining
11.2T tokens in three stages (0 to 8T, 8T to 10T, 10T to 11.1T), then 100B tokens of context extension. Stage 1: The Stack v2, StarCoder2 pull requests, Jupyter and Kaggle notebooks, GitHub issues, StackExchange; stage 2 adds Stack-Edu; stage 3 upsamples high-quality code. Code share: Code 12% in stage 1, 15% in stage 2, 24% in stage 3. Context extension runs two stages of 50B tokens each, from 4k to 32k and then 32k to 64k, upsampling math, code and reasoning data; YaRN allows 128k at inference.
Supervised
A 1.8B-token SFT set (1B non-reasoning, 0.8B reasoning), 4 epochs, after a 140B-token general reasoning mid-training stage; reasoning traces for thin domains were generated by prompting Qwen3-32B. Teacher: Qwen3-32B.
RL or preference
APO (Anchored Preference Optimization, a variant of DPO). Reward: Preference pairs with Qwen3-32B responses as chosen and Qwen3-0.6B responses as rejected; no verifiable reward. Tasks: Not applicable: no RL stage is described. A linear merge of the APO model soup (0.9) with a mid-training checkpoint (0.1) recovered the long-context RULER score lost during reasoning mid-training and alignment.
Result
The blog states LiveCodeBench rises from 15.2% to 30.0% with extended thinking enabled (blog of July 2025).

Moonshot AI2025-06

Kimi-Dev-72B

72B parameters, denseweightsIn the catalog

continued from Qwen2.5-72B-Base

Reusable idea Train Agentless skills (localization, code edit, test writing) first: this skill prior let 5k public trajectories lift the model to 48.6% pass@1 as a SWE-agent.

Read the full recipe
Pretraining
About 150B tokens of mid-training (about 50B Agentless-form diff patches, about 20B curated PR commit packs, about 20B synthetic reasoning and agentic data upsampled 4 times). Millions of GitHub issues and PR commits, with every repository of the SWE-bench Verified test set excluded. The report states mid-training strengthens knowledge of practical bug fixes and unit tests, giving a better starting point for later stages.
Supervised
A cold-start SFT set of reasoning trajectories built on SWE-Gym and SWE-bench-extra, where the teacher acts as both BugFixer and TestWriter; a later agent adaptation uses 5k public trajectories. Teacher: DeepSeek-R1 (20250120 version).
RL or preference
Kimi k1.5 policy optimization (REINFORCE-style policy gradient with group-mean rewards). Reward: Outcome only, 0 or 1: a BugFixer patch must pass all ground-truth unit tests; a TestWriter test must fail without the fix and pass with it. Tasks: Code-edit stage only, on prompts with executable environments; 1,200 problems at pass@16 above 0, with 500 previously excluded prompts re-added every 100 steps. RL targets only the code-edit stage because localization is already strong after mid-training and cold start. Positive samples from recent iterations are added to later batches.
Result
The abstract states Kimi-Dev reaches 60.4% on SWE-bench Verified, the best among workflow approaches (arXiv v3, December 2025).

Skywork (Kunlun)2025-05

Skywork-OR1 (7B and 32B)

7B and 32B parameters, denseweights, data and codeIn the catalog

fine-tuned from DeepSeek-R1-Distill-Qwen-32B and DeepSeek-R1-Distill-Qwen-7B

Reusable idea Filter RL prompts offline and online so training stays on problems that are neither always solved nor never solved, and keep only groups with non-zero advantage in each batch.

Read the full recipe
RL or preference
MAGIC, a modified GRPO (Multi-stage Adaptive entropy scheduling for GRPO In Convergence). Reward: Binary 0 or 1 from a rule-based verifier; code is checked by unit tests in a local sandbox. Tasks: About 13.7K code questions (2.7K LeetCode, 11K TACO), alongside about 105K math problems. Prompts that the base model always or never solves are removed before training, and prompts the actor solved fully in the previous stage are dropped during training. Context length grows over several stages and the KL loss is omitted.
Result
The report states Skywork-OR1-32B scores 63.0 on LiveCodeBench (2024-08 to 2025-02) (report of May 2025).

NVIDIA2025-05

AceReason-Nemotron (7B and 14B)

7B and 14B parameters, denseweightsIn the catalog

fine-tuned from DeepSeek-R1-Distill-Qwen-7B and DeepSeek-R1-Distill-Qwen-14B

Reusable idea Train on math-only prompts first, then code-only prompts, because math-only RL already improved code reasoning and code RL then adds further gains with minimal math degradation.

Read the full recipe
RL or preference
GRPO run strictly on-policy (one gradient update per rollout batch, KL term removed). Reward: Binary: 1 only if the extracted code passes all test cases within the time limit. Tasks: Math-only prompts first, then code-only: 8,520 competitive-programming problems after filtering, with difficulty scored by DeepSeek-R1-671B over 8 rollouts and unsolvable problems removed. Response length is extended in stages from 8K to 16K, 24K and 32K. The report states math-only RL raised LiveCodeBench v5 to 44.4% (7B) and 58.9% (14B) before any code RL.
Result
The report states AceReason-Nemotron-14B improves from 53.1% and 47.9% to 61.1% and 54.9% on LiveCodeBench v5 and v6 (arXiv v3, June 2025).

ByteDance Seed2025-04

Seed-Coder (8B Base, Instruct, Reasoning)

8.2B parameters, denseweightsIn the catalog

no earlier checkpoint named in the report

Reusable idea Start long chain-of-thought RL from the base model plus a small warmup set rather than from the instruct model, because the instruct model collapsed into SFT data patterns during RL.

Read the full recipe
Pretraining
6 trillion tokens: 1T of code-related and math-related web data, 4T of curated code, then 400B and 600B tokens of continued pretraining on high-quality and long-context data. GitHub code filtered by LLM quality scores, 74 million commits from 140K repositories (about 100B tokens), and code-related web data (about 1.2T tokens). FIM ratio is 0.5 in regular pretraining and 0.1 in continued pretraining, and SPM mode performed slightly better than PSM. Context grows from 8K to 32K over about 1T training tokens.
Supervised
Instruct: about 3 million instruction-response pairs, 3 epochs, built from GitHub snippets and style-augmented public instructions, filtered with Tree-sitter and a model scorer, with sandbox self-correction against generated unit tests. Teacher: Unnamed LLMs for the instruct data; DeepSeek-R1 for the Reasoning model's long chain-of-thought warmup solutions.
RL or preference
DPO for the Instruct model; GRPO (verl, DAPO-style changes) for the Reasoning model. Reward: Instruct: on-policy responses scored by generated unit tests in a sandbox. Reasoning: verifiable correctness plus a format reward (the correctness check is not detailed). Tasks: Instruct: about 20,000 preference pairs. Reasoning: CodeContests, ICPC problems, open-r1/codeforces-cots and LiveCodeBench data before August 2024. The Reasoning RL runs 90 steps at 16K with 16 samples per prompt, then 160 steps at 32K with 32 samples, and filters problems with correctness above 87.5%.
Result
The report states Seed-Coder-8B-Instruct reaches 36.2% pass@1 on MHPP, surpassing all other roughly 8B models (report of June 2025).

DeepCoder-14B-Preview

14B parameters, denseweights, data and codeIn the catalog

fine-tuned from DeepSeek-R1-Distill-Qwen-14B

Reusable idea Require at least 5 unit tests per problem and a passing official solution, because problems with fewer tests encourage reward hacking by printing memorized answers.

Read the full recipe
RL or preference
GRPO+, a stabilized GRPO (no entropy loss, no KL loss, overlong filtering, clip high). INF and M-A-P (Nanjing University)2024-11

OpenCoder (1.5B and 8B)

1.5B and 8B parameters, denseweights, data and codeIn the catalog

trained from scratch

Reusable idea Run exact deduplication and then file-level fuzzy deduplication on GitHub code: file-level deduplication removed about 68 billion more tokens (68.4%) after repository-level deduplication.

Read the full recipe
Pretraining
8B: 2.5 trillion tokens (3.5 epochs) plus a 100B-token annealing phase; 1.5B: 2 trillion tokens over four epochs plus 100B annealing. RefineCode plus code-related web data; annealing mix of 83.94B RefineCode tokens, 12.44B algorithmic corpus, 2.71B high-quality code snippets and 0.91B code textbooks. Code share: RefineCode (960B tokens): GitHub code 78.4%, The Stack v2 12.5%, Jupyter notebooks 1.1%; the rest is code-related web and open-source data. Exact deduplication followed by file-level fuzzy deduplication is aggressive and CPU-saving; the report finds file-level beats repository-level and chunk-level deduplication adds nothing. High-quality synthetic data in the annealing stage improved results in the report's ablation.
Supervised
Two stages: stage 1 about 4M theory-focused examples (0.7M RealUser-Instruct, 2.3M Large-scale Diverse-Instruct, 1.0M filtered Infinity-Instruct); stage 2 about 367K code examples (36K McEval-Instruct, 111K Evol-Instruct, 110K Educational-Instruct, 110K Package-Instruct), with synthetic code kept only if generated test cases passed.
RL or preference
No RL or preference stage is reported.
Result
In Table 1 of the report (version of March 2025), OpenCoder-8B chat scores 83.5 pass@1 on HumanEval after 2.5T training tokens.

Alibaba Qwen2024-09

Qwen2.5-Coder (0.5B to 32B)

0.5B, 1.5B, 3B, 7B, 14B and 32B parameters, denseweightsIn the catalog

continued from Qwen2.5

Reusable idea A 70% code, 20% text, 10% math mixture beat a 100% code mixture on Qwen2.5-Coder-7B, so keep text and math in code pretraining.

Read the full recipe
Pretraining
Over 5.5 trillion tokens: 5.2T at file level (8,192 context) and about 300B of long-context repository-level code. Public GitHub repositories created before February 2024, pull requests, commits, Jupyter notebooks and Kaggle datasets; Common Crawl text-code grounding data; synthetic code from CodeQwen1.5 kept only if an executor ran it; Qwen2.5-Math and Qwen2.5 text data. Code share: 70% code, 20% text, 10% math. On Qwen2.5-Coder-7B a 7:2:1 code, text and math ratio beat both 100:0:0 and 85:10:5. Repository-level training extends context from 8,192 to 32,768 tokens, with YaRN allowing up to 131,072.
Supervised
Coarse-to-fine SFT: tens of millions of low-quality but diverse synthetic instruction samples first, then millions of high-quality samples chosen by rejection sampling; multilingual instruction data from language-specific agents, checklist scoring, a multilingual execution sandbox, and a small share of FIM-format instruction samples.
RL or preference
Offline DPO. Reward: Execution feedback from a multilingual code sandbox with generated test cases for self-contained code; LLM-as-a-judge for other code. Tasks: Algorithm-like and self-contained snippets in Python, Java and other languages, plus other code snippets judged by an LLM. Code DPO data is combined with common data for offline DPO training.
Result
The report states Qwen2.5-Coder-32B-Instruct is the current SOTA open-source code model, matching the coding capabilities of GPT-4o (report v3, November 2024).

DeepSeek-AI2024-06

DeepSeek-Coder-V2 (Lite 16B and 236B)

16B total with 2.4B active, and 236B total with 21B active (mixture of experts)weightsIn the catalog

continued from an intermediate checkpoint of DeepSeek-V2 (trained on 4.2T tokens)

Reusable idea Train a reward model on compiler pass/fail data and use it for RL, because raw test-case feedback is noisy when prompts have few tests.

Read the full recipe
Pretraining
6 trillion additional tokens, for 10.2T tokens in total (4.2T from the DeepSeek-V2 checkpoint plus 6T). 1,170B code-related tokens from GitHub and CommonCrawl, 221B math tokens from CommonCrawl, and natural language sampled from the DeepSeek-V2 corpus. Code share: 60% source code, 10% math, 30% natural language. FIM at a 0.5 rate in PSM mode is used for the 16B model only; the 236B model uses next-token prediction only. Context grows to 128K with YaRN in two stages of 1000 steps each, at 32K and then 128K.
Supervised
A 300M-token instruction set built from 20k code instructions, 30k math instructions and some DeepSeek-V2 instruction data; 1B tokens of training.
RL or preference
GRPO. Reward: A reward model trained on compiler feedback (0 or 1 for passing all test cases), used instead of the raw compiler signal. Tasks: About 40k prompts of code and math, each code prompt with test cases. The report states raw 0-1 compiler feedback can be noisy when a prompt has few test cases, and that the reward model generalized better on in-house LeetCode test sets.
Result
The report states 90.2% on HumanEval, 76.2% on MBPP and 43.4% on LiveCodeBench (questions from December 2023 to June 2024).

Reusable idea Train on code only for 3T to 4T tokens, then spend a final 500B tokens on 80% code and 20% high-quality language data to improve reasoning and problem solving.

Read the full recipe
Pretraining
Phase 1: 4T tokens of code for 3B and 8B, 3T for 20B, and 1.4T for 34B after upscaling a 1.6T-token 20B checkpoint; phase 2: 500B tokens; 3.5T to 4.5T in total. Permissively licensed GitHub code, GitHub issues, and in phase 2 technical, mathematics and web documents. Code share: Phase 1 is code only; phase 2 is 80% code and 20% language data. Training mixes causal language modeling and FIM with weight alpha 0.5, in both PSM and SPM modes. Exact and fuzzy deduplication run before training, and files are kept only with permissive licenses.
Supervised
Instruct models use a filtered CommitPackFT (92 languages), math sets (MathInstruct, MetaMathQA), code instruction sets (Glaive-Code-Assistant-v3, Self-OSS-Instruct-SC2, Glaive-Function-Calling-v2, NL2SQL) and language sets (HelpSteer, a license-filtered Platypus).
RL or preference
No RL or preference stage is reported.
Result
The report states Granite-8B-Code-Base outperforms CodeGemma-8B by almost 12 points on HumanEvalPack (33.2% vs 21.3%) with fewer tokens (4.5T vs 7.5T) (report of May 2024).

DeepSeek-Coder (1.3B to 33B)

1.3B to 33B parameters, denseweights

trained from scratch

Reusable idea A 50% FIM rate in PSM mode balances infilling and completion, because a 100% FIM rate gave the best HumanEval-FIM score but the weakest code completion.

Read the full recipe
Pretraining
2 trillion tokens; context extended to 16K with an extra 1000 training steps. GitHub code (798 GB after cleaning), GitHub Markdown and StackExchange, and Chinese articles; project-level corpus organized by dependency parsing. Code share: 87% source code, 10% English code-related natural language, 3% code-unrelated Chinese natural language. Near-deduplication is applied at the repository level, treating the concatenated repository as one sample. FIM uses a 0.5 rate in PSM mode; a 100% FIM rate gave the best HumanEval-FIM score but the weakest code completion.
Supervised
Instruction tuning on helpful human instructions in the Alpaca instruction format, with a 4M-token batch and 2B tokens in total.
Result
The report states that DeepSeek-Coder-Instruct 33B surpasses OpenAI GPT-3.5 Turbo in the majority of the evaluation benchmarks (report of January 2024).

Meta2023-08

Code Llama (7B, 13B, 34B, 70B; Base, Python, Instruct)

7B, 13B, 34B and 70B parameters, denseweightsIn the catalog

continued from Llama 2

Reusable idea Fine-tuning Llama 2 on 500B code tokens beats an identical 7B model trained from scratch on the same mix: the scratch model's loss matches Code Llama's at about half of training, with 240B fewer tokens, and the gap grows.

Read the full recipe
Pretraining
500B tokens for 7B, 13B and 34B; 1T tokens for 70B; Code Llama - Python adds 100B tokens; a long-context stage then uses 16,384-token sequences. A near-deduplicated dataset of publicly available code, plus 8% of samples from natural language datasets related to code and a small share of general natural language. Code share: 85% code, 8% natural language related to code, 7% natural language. The 7B, 13B and 70B models are trained with infilling: documents are split at the character level into prefix, middle and suffix, applied with probability 0.9, half in PSM and half in SPM format. Long-context fine-tuning raises sequence length from 4,096 to 16,384 tokens.
Supervised
Code Llama - Instruct uses Llama 2's 'RLHF V5' instruction set (thousands of SFT and millions of rejection-sampling examples) plus about 14,000 self-instruct question, test and solution triplets, with 6% code and 2% natural language rehearsal data. Teacher: Llama 2 70B wrote 62,000 interview-style questions (about 52,000 after de-duplication); Code Llama 7B wrote the unit tests and ten Python solutions per question.
RL or preference
Reward: Unit tests: the first of ten sampled solutions that passes the generated tests is kept. The report states that execution feedback, not human feedback, is used to select the self-instruct data.
Result
The abstract states scores of up to 67% on HumanEval and 65% on MBPP (arXiv v3, January 2024).
