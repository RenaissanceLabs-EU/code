Start here: a minimal setup

A newcomer needs very little: one environment, the Hugging Face libraries, a trainer, and an evaluation harness. Then add pieces only when a step becomes the bottleneck.

Minimal local setup

A laptop or a single GPU: fine-tune a small model with LoRA, build datasets, and run a first EvalPlus check. Needs Python 3.11 or newer; the macOS system Python 3.9.6 cannot install current TRL.

  1. Check the Python version

    shell
    python3.12 --version

    TRL, Transformers, PEFT and Accelerate all declare Requires-Python >=3.11; datasets >=3.10; EvalPlus >=3.9. Install Python 3.11 to 3.13 first (python.org installer, or uv python install 3.12). On Python 3.9, pip only offers TRL up to 0.24.0.

  2. Create and activate a virtual environment

    shell
    python3.12 -m venv .venv && source .venv/bin/activate && python -m pip install --upgrade pip

    Use one environment per training framework.

  3. Install the training stack

    shell
    pip install "torch>=2.6.0" "transformers>=4.56.2" "datasets>=4.7.0" "peft>=0.18.0" "accelerate>=1.11.0" trl

    Floors are from TRL's pyproject.toml (transformers>=4.56.2, accelerate>=1.11.0, datasets>=4.7.0, torch>=2.6.0, peft extra >=0.18.0). On 2026-11-25 the latest releases were transformers 5.24.1, datasets 5.2.0, peft 0.22.0, accelerate 1.16.0, trl 1.18.2, and their declared requirements did not conflict. For a CUDA build of torch, follow pytorch.org first.

  4. Install the evaluator

    shell
    pip install evalplus

    EvalPlus 0.3.1 (2024-10-20) declares Python >=3.9 and transformers>=4.43.0, datasets>=2.21.0, tree-sitter>=0.22.0. It also pulls openai, anthropic and google-generativeai client packages. Add the vllm extra only on a Linux GPU box.

  5. Check the environment

    shell
    pip check && python -c "import transformers, datasets, peft, trl, accelerate; print(transformers.__version__, datasets.__version__, peft.__version__, trl.__version__, accelerate.__version__)"

    Run this before any training. It catches version conflicts that pip install can leave behind.

  6. Log in to the Hub (optional)

    shell
    hf auth login

    Needed for gated models and datasets and for pushing checkpoints. The hf CLI comes with huggingface_hub.

  7. Smoke-test one SFT run

    shell
    trl sft --model_name_or_path Qwen/Qwen2.5-0.5B --dataset_name trl-lib/Capybara --output_dir Qwen2.5-0.5B-SFT

    Command from TRL's README. It proves the stack works; swap in your own prompt/completion code dataset and add a peft config for LoRA before a real run.

  8. Generate samples, then execute them in Docker

    shell
    evalplus.codegen --model Qwen/Qwen2.5-Coder-1.5B --dataset humaneval --backend hf --greedy
docker run --rm --pull=always -v $(pwd)/evalplus_results:/app ganler/evalplus:latest evalplus.evaluate --dataset humaneval --samples /app/humaneval/Qwen--Qwen2.5-Coder-1.5B_hf_temp_0.0.jsonl

    Pattern from EvalPlus's README (safe execution within Docker). The samples filename follows the README's org--model_backend_temp_X.jsonl naming; check the actual file name that codegen wrote. Do not run generated code directly on your laptop.

Scaling up

A multi-GPU node or a Slurm cluster: multi-GPU SFT, vLLM sampling, an RL framework with execution-based rewards, a code sandbox and larger evaluation runs.

  1. Create the training environment

    shell
    python3.12 -m venv .venv && source .venv/bin/activate && pip install "trl[peft,deepspeed]"

    TRL's extras peft (>=0.18.0) and deepspeed (>=0.18.6) exist in its pyproject. Install a CUDA build of torch matching the cluster first. Keep verl, SkyRL, OpenRLHF and Axolotl in separate environments because they pin different versions.

  2. Launch multi-GPU training on one node

    shell
    accelerate launch --multi_gpu --num_processes 4 train.py
# or, as TRL's docs do:
torchrun --nproc_per_node 8 train.py

    accelerate launch syntax is from Accelerate's launch tutorial. For ZeRO, set deepspeed="<config.json>" in SFTConfig (TRL's DeepSpeed page) and launch with torchrun, or use: trl sft ... --deepspeed examples/deepspeed_configs/zero2.json from a TRL clone.

  3. Submit the same job to Slurm

    shell
    #SBATCH --nodes=1
#SBATCH --ntasks-per-node=1
#SBATCH --gres=gpu:4
export GPUS_PER_NODE=4
accelerate launch --num_processes $GPUS_PER_NODE train.py

# multi-node, from the same example set:
head_node_ip=$(scontrol show hostnames $SLURM_JOB_NODELIST | head -n 1)
LAUNCHER="accelerate launch --num_processes $((SLURM_NNODES * GPUS_PER_NODE)) --num_machines $SLURM_NNODES --rdzv_backend c10d --main_process_ip $head_node_ip --main_process_port 29500"
srun $LAUNCHER train.py

    Adapted from Accelerate's examples/slurm/submit_multigpu.sh and submit_multinode.sh (those also set job name, output files, cpus-per-task and time, and source an environment). Replace the script with your training script.

  4. Start a vLLM sampling server

    shell
    pip install "trl[vllm]"
CUDA_VISIBLE_DEVICES=0,1,2,3 VLLM_SERVER_DEV_MODE=1 vllm serve Qwen/Qwen2.5-7B --gpu-memory-utilization 0.9 --tensor-parallel-size 4 \
    --weight-transfer-config '{"backend": "nccl"}' --logprobs-mode processed_logprobs --max-logprobs -1

    From TRL's vLLM integration page. The server and the trainer must run on separate GPUs. For plain sampling or evaluation, the vLLM quickstart shows: uv pip install vllm --torch-backend=auto, then: vllm serve Qwen/Qwen2.5-1.5B-Instruct.

  5. Run GRPO against that server

    shell
    CUDA_VISIBLE_DEVICES=4,5,6,7 torchrun --nproc_per_node 4 train.py

    train.py builds a GRPOTrainer with GRPOConfig(use_vllm=True, vllm_mode="server") and your reward function (TRL docs). For code, make the reward call the sandbox below.

  6. Or use a dedicated RL framework (verl)

    shell
    git clone https://github.com/verl-project/verl && cd verl
UV_RUN="uv run --frozen --all-packages --extra vllm --extra fsdp"
$UV_RUN python3 examples/data_preprocess/gsm8k.py --local_save_dir ~/data/gsm8k
$UV_RUN python3 -m verl.trainer.main_ppo data.train_files=$HOME/data/gsm8k/train.parquet data.val_files=$HOME/data/gsm8k/test.parquet data.train_batch_size=256 data.max_prompt_length=512 data.max_response_length=512 actor_rollout_ref.model.path=Qwen/Qwen2.5-0.5B-Instruct actor_rollout_ref.actor.optim.lr=1e-6 actor_rollout_ref.actor.ppo_mini_batch_size=64 actor_rollout_ref.actor.ppo_micro_batch_size_per_gpu=4 actor_rollout_ref.rollout.name=vllm actor_rollout_ref.rollout.log_prob_micro_batch_size_per_gpu=8 actor_rollout_ref.rollout.tensor_model_parallel_size=1 actor_rollout_ref.rollout.gpu_memory_utilization=0.4 actor_rollout_ref.ref.log_prob_micro_batch_size_per_gpu=4 critic.optim.lr=1e-5 critic.model.path=Qwen/Qwen2.5-0.5B-Instruct critic.ppo_micro_batch_size_per_gpu=4 algorithm.kl_ctrl.kl_coef=0.001 trainer.logger=console trainer.val_before_train=False trainer.n_gpus_per_node=1 trainer.nnodes=1 trainer.save_freq=10 trainer.test_freq=10 trainer.total_epochs=15 ray_kwargs.ray_init.runtime_env.py_executable="${UV_RUN}"

    From verl's quickstart (GSM8K math, PPO, one GPU with at least 24 GB) with its uv wrapper. verl's uv workflow targets Linux and Python 3.12. For code, point reward.custom_reward_function.path and .name at a compute_score(data_source, solution_str, ground_truth, extra_info) function, as in data/snippets.json verl-grpo-code-reward. Alternatives: SkyRL (docker run -it --runtime=nvidia --gpus all --shm-size=8g --name skyrl novaskyai/skyrl-train-ray-2.57.0-py3.12-cu13.0 /bin/bash, then git clone https://github.com/novasky-ai/SkyRL.git) or OpenRLHF (pip install openrlhf[vllm] inside nvcr.io/nvidia/pytorch:26.03-py3, then ray start --head and ray job submit ... python3 -m openrlhf.cli.train_ppo_ray).

  7. Run generated code in a sandbox service

    shell
    docker run -it -p 8080:8080 volcengine/sandbox-fusion:server-20250609
curl 'http://localhost:8080/run_code' -H 'Content-Type: application/json' --data-raw '{"code": "print(\"Hello, world!\")", "language": "python"}'

    From SandboxFusion's get-started page (the docs write the host as a site constant; localhost:8080 follows from the -p 8080:8080 mapping). Its docs state no isolation strength, so run it where a breakout is acceptable, or put gVisor or a VM under it.

  8. Or use a hardened container per candidate program

    shell
    docker run --rm --network none --read-only --memory 256m --memory-swap 256m --cpus 1 --pids-limit 64 --cap-drop ALL --security-opt no-new-privileges --user 65534:65534 --tmpfs /tmp:rw,noexec,nosuid,size=16m -v "$PWD/job:/work:ro" -w /work python:3.12-slim timeout 10 python candidate.py

    Run on Docker 29.1.3 on 2026-11-24 (data/snippets.json docker-hardened-sandbox). Containers share the host kernel; for adversarial code add gVisor (runsc), a Firecracker microVM, or a hosted sandbox (E2B, Modal).

  9. Evaluate at scale

    shell
    evalplus.codegen --model <your-model> --dataset humaneval --backend vllm --greedy
docker run --rm --pull=always -v $(pwd)/evalplus_results:/app ganler/evalplus:latest evalplus.evaluate --dataset humaneval --samples /app/humaneval/<samples-file>.jsonl

uv tool install harbor
harbor run --dataset terminal-bench@2.0 --agent claude-code --model anthropic/claude-opus-5-5 --n-concurrent 4

    EvalPlus (pip install "evalplus[vllm]") and Harbor commands are from their READMEs. Harbor needs Python 3.12, Docker and a model API key; it runs tasks in local Docker by default and on cloud sandboxes with --env.
