How code models are trained: a reading list

70 papers, technical reports, posts and courses, in the order a practitioner would want them: foundations, data, model reports, instruction data, preference and reinforcement learning, evaluation, tooling. Each one says what you take away from it. Every link was opened and every title, author and year checked on its page.

1. Foundations · Paper2021 · arXiv

Evaluating Large Language Models Trained on Code

Mark Chen et al.

Introduces HumanEval, the function-from-docstring test set that later code papers report against, and shows that repeated sampling lifts the solve rate from 28.8% to 70.2% at 100 samples per problem. Lists concrete failures: docstrings that describe long chains of operations and binding operations to variables.

Result On HumanEval, a new evaluation set we release to measure functional correctness for synthesizing programs from docstrings, our model solves 28.8% of the problems, while GPT-3 solves 0% and GPT-J solves 11.4%.

1. Foundations · Paper2022 · arXiv

CodeGen: An Open Large Language Model for Code with Multi-Turn Program Synthesis

Erik Nijkamp et al.

Releases models up to 16.1B parameters together with the JAXFORMER training library, so the training setup is readable. Builds the Multi-Turn Programming Benchmark (115 problem sets split into multi-turn prompts) and shows that the same intent given over several turns improves synthesis over a single turn.

Result To democratize this, we train and release a family of large language models up to 16.1B parameters, called CODEGEN, on natural language and programming language data, and open source the training library JAXFORMER.

1. Foundations · Paper2022 · arXiv

Competition-Level Code Generation with AlphaCode

Yujia Li et al.

Names three components behind the result: a clean competitive programming dataset, large and efficient-to-sample transformer architectures, and large-scale sampling followed by filtering on program behavior down to a small set of submissions. Read it to see that the sampling and filtering stage, not the base model alone, produces the Codeforces ranking.

Result In simulated evaluations on recent programming competitions on the Codeforces platform, AlphaCode achieved on average a ranking of top 54.3% in competitions with more than 5,000 participants.

1. Foundations · Paper2022 · arXiv

Efficient Training of Language Models to Fill in the Middle

Mohammad Bavarian et al.

Reports ablations on how often to apply the transformation, the structure of the transformation, and how to pick the infill span, and turns them into default settings. Shows that training with a large fraction of transformed data does not harm left-to-right ability as measured by perplexity and sampling evaluations.

Result We show that autoregressive language models can learn to infill text after we apply a straightforward transformation to the dataset, which simply moves a span of text from the middle of a document to its end.

1. Foundations · Paper2022 · arXiv

InCoder: A Generative Model for Code Infilling and Synthesis

Daniel Fried et al.

Shows the training transform: regions of each code file are masked and moved to the end so the model learns infilling with bidirectional context. Evaluates zero-shot infilling on type inference, comment generation, and variable renaming, and finds bidirectional context helps there while left-to-right synthesis stays comparable at similar scale.

Result We introduce InCoder, a unified generative model that can perform program synthesis (via left-to-right generation) as well as editing (via infilling).

Code Llama: Open Foundation Models for Code

Baptiste Rozière et al.

Lays out one recipe producing three flavors from a Llama 2 base: foundation, Python specialization, and instruct, each at 7B, 13B, 34B, and 70B. All models train on 16k-token sequences and improve on inputs up to 100k tokens, and Code Llama - Python 7B beats Llama 2 70B on HumanEval and MBPP.

Result We release Code Llama, a family of large language models for code based on Llama 2 providing state-of-the-art performance among open models, infilling capabilities, support for large input contexts, and zero-shot instruction following ability for programming tasks.

2. Pretraining data · Paper2022 · arXiv

The Stack: 3 TB of permissively licensed source code

Denis Kocetkov et al.

Describes how a 3.1 TB, 30-language dataset is collected, how the permissively licensed subset is built, and the governance plan with an opt-out process and the Am I in The Stack search tool. Trains 350M-parameter decoders on Python subsets to measure the effect of near-deduplication and of license filtering.

Result We find that (1) near-deduplicating the data significantly boosts performance across all experiments, and (2) it is possible to match previously reported HumanEval and MBPP performance using only permissively licensed data.

2. Pretraining data · Paper2022 · arXiv

Training Compute-Optimal Large Language Models

Jordan Hoffmann et al.

The baseline for token-budget decisions in any pretraining run, including code. It trains over 400 models from 70 million to over 16 billion parameters on 5 to 500 billion tokens and checks the prediction with Chinchilla, a 70B model using 4x more data than Gopher at the same compute. It is not code-specific, so read it before the code scaling paper to see what that paper changes.

Result By training over 400 language models ranging from 70 million to over 16 billion parameters on 5 to 500 billion tokens, we find that for compute-optimal training, the model size and the number of training tokens should be scaled equally: for every doubling of model size the number of training tokens should also be doubled.

2. Pretraining data · Paper2024 · arXiv

Arctic-SnowCoder: Demystifying High-Quality Data in Code Pretraining

Yuxiang Wei et al.

Describes a three-phase schedule: 500B standard-quality tokens, then 50B tokens picked by a BERT-style quality annotator plus instruction data, then 5B synthetic tokens from Llama-3.1-70B seeded with phase-two data. The 1.3B model trained on 555B tokens surpasses StarCoder2-3B on HumanEval+, which was pretrained on over 3.3T tokens.

Result Most importantly, we find that the key to high-quality data is its alignment with the distribution of downstream applications.

2. Pretraining data · Paper2024 · arXiv

To Code, or Not To Code? Exploring Impact of Code in Pre-training

Viraat Aryabumi et al.

Gives measured effects of adding code to pretraining on non-code tasks for models of 470M to 2.8B parameters: up to 8.2% relative gain in natural language reasoning, 4.2% in world knowledge, 6.6% in generative win-rates, and a 12x boost in code performance. Supports keeping a code share in general pretraining mixes and spending effort on code quality.

Result Across settings, we find a consistent results that code is a critical building block for generalization far beyond coding tasks and improvements to code quality have an outsized impact across all tasks.

2. Pretraining data · Paper2025 · arXiv

Scaling Laws for Code: Every Programming Language Matters

Jian Yang et al.

Built on 1000+ experiments across model sizes from 0.2B to 14B parameters and datasets up to 1T tokens. Finds that interpreted languages such as Python gain more from added model size and data than compiled languages such as Rust, and that pairing code with its translations (parallel pairing) improves cross-lingual ability.

Result Finally, a proportion-dependent multilingual scaling law is proposed to optimally allocate training tokens by prioritizing high-utility PLs (e.g., Python), balancing high-synergy pairs (e.g., JavaScript-TypeScript), and reducing allocation to fast-saturating languages (Rust), achieving superior average performance across all PLs compared to uniform distribution under the same compute budget.
