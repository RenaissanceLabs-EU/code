Objective

Fine-tune Qwen2.5-Coder-1.5B-Instruct with LoRA (TRL SFTTrainer) on about 4,000 filtered, execution-checked instruction examples from nvidia/OpenCodeInstruct, then measure the change with EvalPlus (HumanEval+ and MBPP+), a held-out slice of the same dataset executed in a sandbox, and a regression check. The point is a complete, inspectable, reproducible loop (prepare, train, merge, evaluate, publish), not a record score.

Run it: the steps

  1. Create two Python 3.11 or 3.12 virtual environments (training and evaluation) and install requirements-train.txt and requirements-eval.txt.
  2. python prepare_data.py --out data (add --rl-pool 3000 for the stretch recipe). Read data/manifest.json and look at 20 rows by eye.
  3. Baseline first: run eval.sh sections 1 to 3 for the BASE model only and keep the logs. Compare with the published numbers in evaluation.baseline.
  4. Smoke test: python train_sft.py --max-steps 5 --out out/smoke. Check that loss is finite, memory is under your limit and the adapter is saved.
  5. Train: python train_sft.py (or bash trl_sft_cli.sh). Note peak memory and wall-clock time.
  6. python merge_push.py --adapter out/sft-lora --out out/merged
  7. Run eval.sh again for the tuned model, then python eval_heldout.py compare and the sanity script. Fill the table in model_card.md.
  8. Optional: --push your-name/model-name after reading the dataset attribution rule and checking the card; keep the adapter too.

Dataset

nvidia/OpenCodeInstruct, pinned to revision 8f3ba5bafe4d6e8db46082cf7ae6741bc370604d.

  • Subset and filter. Stream the 'train' config (50 parquet shards, about 115 to 133 MB each, 6.86 GB download, 5,000,000 rows). shuffle(seed=42, buffer_size=20000), keep rows passing the filter rule, stop at 4,500 kept rows (4,000 train + 200 validation + 300 held-out). Filter rule: (1) average_test_score == 1 and tests_execution_status all 'pass' with at least 5 tests; (2) llm_judgement scores all equal 5 for the three criteria; (3) the output has a ```python block with no input(), network, subprocess, file-open, sleep, random or clock calls; (4) input plus output at most 6,000 characters; (5) exact duplicate questions removed; (6) any shared 10-word gram with HumanEval or MBPP text removes the row; (7) held-out and validation rows with 5-word-shingle Jaccard above 0.5 to any training question are dropped.
  • Size. Final: about 4,000 train, 200 validation, 300 held-out (the last two shrink slightly after the near-duplicate guard). ESTIMATE of the scan: the filter kept 66 of 500 rows (13 percent) on a non-random sample read from the datasets server (earlier 11 percent on 600 rows), so reaching 4,500 kept rows needs roughly 35,000 to 45,000 streamed rows; datasets.shuffle fills its buffer from up to 10 shards, so expect to transfer up to about 1.2 GB (10 shards), likely less. Token count estimate: median kept row is 1,311 characters (n=66); at an assumed 3.5 characters per token plus about 40 template tokens that is roughly 400 to 450 tokens per example, so about 1.8M tokens per epoch.
  • Split. Deterministic: sort kept rows by md5(id) mod 10,000, first 300 held-out, next 200 validation, next 4,000 train. Held-out and validation rows are never trained on; row ids are written to train_ids.txt and validation_ids.txt. Held-out tests are re-run against the reference solutions in your own sandbox and failing rows are dropped before use.
  • Why this dataset. Rows carry unit tests and execution results, so the same data feeds filtering, training, held-out evaluation and the stretch RL pool. CC-BY-4.0 and Apache-2.0 generators give a clean license chain. The OpenCodeInstruct paper (Table 4, Qwen2.5-Coder-7B, 500k rows) found that selecting rows with LLM judgment score 5 beat random selection (HumanEval+ 80.5 vs 77.8, MBPP+ 71.4 vs 70.1) and that unit-test-passing rows were marginally better than random; QLoRA (arXiv 2305.14314) reports data quality matters far more than size (9k OASST1 beat 450k FLAN v2). Rejected alternatives: KodCode-V1 and KodCode-Light-RL-10K are CC-BY-NC-4.0 (HF API), so not clean for commercial reuse; Magicoder-OSS-Instruct-75K is MIT but generated by GPT-3.5 (OpenAI terms apply) and has no tests; bigcode/self-oss-instruct-sc2-exec-filter-50k (ODC-By, 50,661 rows) has no separate test field.
  • License. CC-BY-4.0 (dataset card and HF API). Attribution to NVIDIA is required; the model card template includes it. The card adds that users must check the license of each dataset they use.
  • Terms of the model that wrote it. Per the OpenCodeInstruct paper (arXiv 2504.04030, read 2026-11-25): responses, the 10 unit tests per question and the quality judgments were produced by Qwen2.5-Coder-32B-Instruct (Apache-2.0 per HF API); seed instructions were written by Qwen2.5-32B-Instruct (Apache-2.0 per HF API) from Python functions collected from GitHub, plus 25,443 algorithmic questions from TACO (Apache-2.0 per its dataset card). Apache-2.0 places no restriction on using model outputs to train other models. Open points: the model that ran the Genetic-Instruct mutation and crossover step is not named in the sections read (the Genetic-Instruct paper's own experiment used Mixtral-8x22B); the licenses of the GitHub functions and the original competitive-programming statements behind the seeds were not checked.
  • Limits. Both the answers and the tests were written by a model; the tests were only checked against that model's own answer, so a passing test proves consistency, not correctness. The dataset is stored in blocks (the first 100 rows at offsets 0, 300000 and 1000000 are all 'generic', at 100000 and 500000 all 'algorithmic', all 'self-instruct'), so never take the first N rows: always shuffle. Instructions were evolved from shared seeds, so near-duplicates exist; the Jaccard guard reduces but does not remove this leakage into the held-out slice. The dataset authors state n-gram decontamination against benchmarks (open-r1 script); the benchmark list was not verified, so prepare_data.py adds its own check against HumanEval and MBPP.

prepare_data.py
"""Build the SFT, validation and held-out sets from nvidia/OpenCodeInstruct (CC-BY-4.0).

Run once. Streams the dataset (no full download), keeps only rows that pass strict filters,
removes overlap with HumanEval and MBPP, splits by a hash of the row id, and writes JSONL files:

  data/oci-sft-4k/train.jsonl        prompt/completion rows for TRL (conversational prompt-completion)
  data/oci-sft-4k/*_ids.txt          row ids of each split, same order
  data/oci-sft-4k/validation.jsonl   same format, used only for eval loss
  data/oci-heldout/heldout.jsonl     question, tests and reference solution, never trained on
  data/oci-rl-pool/pool.jsonl        optional pool for the stretch GRPO recipe (--rl-pool N)
  data/manifest.json                 counts, dataset revision, filter rule, seed

Usage:  python prepare_data.py --out data
"""
import argparse
import hashlib
import json
import random
import re
from pathlib import Path

DATASET = "nvidia/OpenCodeInstruct"
# Commit of the dataset repo read from the Hugging Face API on 2026-11-25.
REVISION = "8f3ba5bafe4d6e8db46082cf7ae6741bc370604d"
SEED = 42

# Programs that need the network, a terminal or the filesystem make unit tests flaky; drop them.
BAD_CODE = re.compile(
    r"\binput\s*\(|\brequests\b|\burllib\b|\bsocket\b|\bsubprocess\b|os\.system|\bopen\s*\(|"
    r"\bsleep\s*\(|random\.|datetime\.now|time\.time"
)
CODE_BLOCK = re.compile(r"```python\n(.*?)```", re.S)


def words(text):
    return re.findall(r"\w+", text.lower())


def ngrams(text, n):
    w = words(text)
    return {" ".join(w[i:i + n]) for i in range(len(w) - n + 1)}


def judged_all_five(raw):
    """llm_judgement is a JSON string with three criteria, each {score, justification}."""
    try:
        j = json.loads(raw)
        return len(j) >= 3 and all(v.get("score") == 5 for v in j.values())
    except Exception:
        return False


def keep(row):
    """Filter rule. Returns the parsed tests list or None.

    1. all generated unit tests passed on the reference solution (average_test_score == 1)
    2. every entry of tests_execution_status is "pass" and there are at least 5 tests
    3. the LLM judge gave 5 out of 5 on all three criteria (OpenCodeInstruct paper, Table 4)
    4. the response has a ```python block, and the code passes the BAD_CODE screen
    5. question plus answer is at most 6000 characters (fits max_length 2048 tokens)
    """
    try:
        if float(row["average_test_score"]) != 1.0:
            return None
        tests = json.loads(row["unit_tests"])
        status = json.loads(row["tests_execution_status"])
    except Exception:
        return None
    if len(tests) < 5 or len(status) != len(tests) or any(s != "pass" for s in status):
        return None
    if not judged_all_five(row["llm_judgement"]):
        return None
    m = CODE_BLOCK.search(row["output"])
    if not m or BAD_CODE.search(m.group(1)):
        return None
    if len(row["input"]) + len(row["output"]) > 6000:
        return None
    return tests


def benchmark_ngrams(n=10):
    """Own decontamination on top of the dataset's: 10-word grams of HumanEval and MBPP."""
    from datasets import load_dataset

    grams = set()
    for r in load_dataset("openai/openai_humaneval", split="test"):
        grams |= ngrams(r["prompt"] + "\n" + r["canonical_solution"], n)
    mbpp = load_dataset("google-research-datasets/mbpp", "full")
    for split in mbpp:
        for r in mbpp[split]:
            grams |= ngrams(r["text"] + "\n" + r["code"], n)
    return grams


def bucket(row_id):
    return int(hashlib.md5(row_id.encode()).hexdigest(), 16) % 10_000


def jaccard(a, b):
    return len(a & b) / max(1, len(a | b))


def main():
    from datasets import load_dataset

    ap = argparse.ArgumentParser()
    ap.add_argument("--out", default="data")
    ap.add_argument("--n-train", type=int, default=4000)
    ap.add_argument("--n-val", type=int, default=200)
    ap.add_argument("--n-heldout", type=int, default=300)
    ap.add_argument("--rl-pool", type=int, default=0, help="extra rows for the stretch recipe")
    ap.add_argument("--max-scan", type=int, default=400_000, help="stop after this many streamed rows")
    a = ap.parse_args()

    want = a.n_train + a.n_val + a.n_heldout + a.rl_pool
    bench = benchmark_ngrams()
    stream = load_dataset(DATASET, split="train", streaming=True, revision=REVISION)
    # shuffle() reorders the shards and uses a buffer over up to 10 shards at a time (datasets docs),
    # which mixes the "generic" and "algorithmic" domains that are stored in separate blocks.
    stream = stream.shuffle(seed=SEED, buffer_size=20_000)

    kept, seen_inputs, scanned = [], set(), 0
    stats = {"scanned": 0, "filtered_out": 0, "contaminated": 0, "duplicate": 0}
    for row in stream:
        scanned += 1
        if scanned > a.max_scan or len(kept) >= want:
            break
        tests = keep(row)
        if tests is None:
            stats["filtered_out"] += 1
            continue
        key = re.sub(r"\s+", " ", row["input"].strip().lower())
        if key in seen_inputs:
            stats["duplicate"] += 1
            continue
        if ngrams(row["input"] + "\n" + row["output"], 10) & bench:
            stats["contaminated"] += 1
            continue
        seen_inputs.add(key)
        kept.append({"id": row["id"], "input": row["input"], "output": row["output"],
                     "domain": row["domain"], "tests": tests})
    stats["scanned"] = scanned
    print("kept", len(kept), stats)

    # Deterministic split by hash of id: first held-out, then validation, then train, then RL pool.
    kept.sort(key=lambda r: bucket(r["id"]))
    heldout = kept[:a.n_heldout]
    val = kept[a.n_heldout:a.n_heldout + a.n_val]
    train = kept[a.n_heldout + a.n_val:a.n_heldout + a.n_val + a.n_train]
    pool = kept[a.n_heldout + a.n_val + a.n_train:]

    # Leakage guard: instructions in this dataset are evolved from shared seeds, so drop held-out and
    # validation rows whose 5-word shingles overlap a training row (Jaccard > 0.5).
    train_sh = [ngrams(r["input"], 5) for r in train]

    def clean(rows):
        out = []
        for r in rows:
            sh = ngrams(r["input"], 5)
            if all(jaccard(sh, t) <= 0.5 for t in train_sh):
                out.append(r)
        return out

    heldout_c, val_c = clean(heldout), clean(val)
    print("near-duplicates dropped: heldout", len(heldout) - len(heldout_c), "val", len(val) - len(val_c))

    out = Path(a.out)
    for d in ("oci-sft-4k", "oci-heldout", "oci-rl-pool"):
        (out / d).mkdir(parents=True, exist_ok=True)

    def write(path, rows):
        with open(path, "w") as f:
            for r in rows:
                f.write(json.dumps(r, ensure_ascii=False) + "\n")

    def sft(r):
        return {"prompt": [{"role": "user", "content": r["input"]}],
                "completion": [{"role": "assistant", "content": r["output"]}]}

    # ids live in separate files so the JSONL has only the columns TRL needs
    (out / "oci-sft-4k" / "train_ids.txt").write_text("\n".join(r["id"] for r in train))
    (out / "oci-sft-4k" / "validation_ids.txt").write_text("\n".join(r["id"] for r in val_c))
    write(out / "oci-sft-4k" / "train.jsonl", [sft(r) for r in train])
    write(out / "oci-sft-4k" / "validation.jsonl", [sft(r) for r in val_c])
    write(out / "oci-heldout" / "heldout.jsonl",
          [{"id": r["id"], "input": r["input"], "tests": r["tests"], "reference_output": r["output"]}
           for r in heldout_c])
    if pool:
        rng = random.Random(SEED)
        rows = []
        for r in pool:
            t = list(r["tests"])
            rng.shuffle(t)  # 6 tests drive the reward, the rest stay hidden to detect reward hacking
            rows.append({"id": r["id"], "prompt": [{"role": "user", "content": r["input"]}],
                         "reward_tests": t[:6], "holdout_tests": t[6:]})
        write(out / "oci-rl-pool" / "pool.jsonl", rows)

    manifest = {"dataset": DATASET, "revision": REVISION, "seed": SEED, "stats": stats,
                "counts": {"train": len(train), "validation": len(val_c),
                           "heldout": len(heldout_c), "rl_pool": len(pool) if pool else 0},
                "filter": keep.__doc__}
    (out / "manifest.json").write_text(json.dumps(manifest, indent=2))


if __name__ == "__main__":
    main()
train_sft.py
"""LoRA supervised fine-tuning of Qwen2.5-Coder-1.5B-Instruct on the filtered OpenCodeInstruct subset.

Verified against TRL 1.18.2, PEFT 0.22.0, transformers 5.24.1 (API names read from source on 2026-11-25).
Not executed by the authors of this recipe: treat the first run as a smoke test (--max-steps 5).

  python train_sft.py                                  # primary: 1.5B model, ~250 optimizer steps
  python train_sft.py --model Qwen/Qwen2.5-Coder-0.5B-Instruct --rank 16 --batch 2 --accum 16   # fallback
"""
import argparse

import torch
from datasets import load_dataset
from peft import LoraConfig
from trl import SFTConfig, SFTTrainer


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--model", default="Qwen/Qwen2.5-Coder-1.5B-Instruct")
    ap.add_argument("--data", default="data/oci-sft-4k")
    ap.add_argument("--out", default="out/sft-lora")
    ap.add_argument("--lr", type=float, default=1e-4)
    ap.add_argument("--epochs", type=float, default=2.0)
    ap.add_argument("--rank", type=int, default=32)
    ap.add_argument("--batch", type=int, default=4, help="per-device micro batch size")
    ap.add_argument("--accum", type=int, default=8, help="gradient accumulation steps")

        max_steps=a.max_steps,
        per_device_train_batch_size=a.batch,
        per_device_eval_batch_size=a.batch,
        gradient_accumulation_steps=a.accum,
        learning_rate=a.lr,
        lr_scheduler_type="cosine",
        warmup_steps=0.05,            # transformers 5.x: a float below 1 is a ratio of total steps
        weight_decay=0.0,
        max_grad_norm=1.0,
        eos_token=a.eos_token,        # None keeps the tokenizer eos (<|im_end|> for the Instruct models)
        max_length=a.max_length,      # SFTConfig name for the sequence limit (default 1024)
        packing=False,                # bfd packing needs flash-attention padding-free mode

        bf16=use_bf16,

        model_init_kwargs={"dtype": dtype},
        eval_strategy="steps",
        eval_steps=50,
        save_strategy="steps",
        save_steps=50,
        save_total_limit=2,
        logging_steps=10,
        seed=a.seed,
        data_seed=a.seed,
        report_to="none",
    )

        model=a.model,
        args=args,
        train_dataset=data["train"],
        eval_dataset=data["validation"],
        peft_config=peft_config,
    )

def extract_code(text):
    blocks = re.findall(r"```(?:python|py)?[ \t]*\n(.*?)```", text, re.S)
    return blocks[0] if blocks else text


def read_jsonl(path):
    with open(path) as f:
        return [json.loads(line) for line in f if line.strip()]


def write_jsonl(path, rows):
    os.makedirs(os.path.dirname(path) or ".", exist_ok=True)
    with open(path, "w") as f:
        for r in rows:
            f.write(json.dumps(r, ensure_ascii=False) + "\n")


def load_model(name):
    import torch
    from transformers import AutoModelForCausalLM, AutoTokenizer

    dev = "cuda" if torch.cuda.is_available() else ("mps" if torch.backends.mps.is_available() else "cpu")
    dtype = torch.bfloat16 if dev == "cuda" else torch.float32
    tok = AutoTokenizer.from_pretrained(name)
    model = AutoModelForCausalLM.from_pretrained(name, dtype=dtype).to(dev)
    model.eval()
    return tok, model, dev


def chat(tok, model, dev, user_text, max_new_tokens):
    import torch

    text = tok.apply_chat_template([{"role": "user", "content": user_text}], tokenize=False,
                                   add_generation_prompt=True)
    ids = tok([text], return_tensors="pt").to(dev)
    with torch.inference_mode():
        # Greedy. generation_config.json of the model (for Qwen: repetition_penalty 1.1) still applies,
        # so keep that file identical between the base and the merged model.
        out = model.generate(**ids, do_sample=False, max_new_tokens=max_new_tokens)
    new = out[0][ids["input_ids"].shape[1]:]
    finished = len(new) < max_new_tokens  # stopped on an end token instead of hitting the limit
    return tok.decode(new, skip_special_tokens=True), finished


def cmd_generate(a):
    tok, model, dev = load_model(a.model)
    rows = read_jsonl(a.data)
    out = []
    for i, r in enumerate(rows):
        text, finished = chat(tok, model, dev, r["input"], MAX_NEW_TOKENS)
        out.append({"id": r["id"], "output": text, "finished": finished})
        if i % 25 == 0:
            print(i, "/", len(rows), flush=True)
    write_jsonl(a.out, out)


def cmd_reference(a):
    rows = read_jsonl(a.data)
    write_jsonl(a.out, [{"id": r["id"], "output": r["reference_output"], "finished": True} for r in rows])


def run_case(code, tests, docker, timeout=30):
    marker = "RESULT-" + uuid.uuid4().hex + ":"
    with tempfile.TemporaryDirectory() as tmp:
        os.chmod(tmp, 0o755)
        with open(os.path.join(tmp, "runner.py"), "w") as f:
            f.write(RUNNER)
        with open(os.path.join(tmp, "case.json"), "w") as f:
            json.dump({"code": code, "tests": tests}, f)
        if docker:
            cmd = ["docker", "run", "--rm", "--network", "none", "--read-only", "--memory", "256m",
                   "--memory-swap", "256m", "--cpus", "1", "--pids-limit", "64", "--cap-drop", "ALL",
                   "--security-opt", "no-new-privileges", "--user", "65534:65534",
                   "--tmpfs", "/tmp:rw,noexec,nosuid,size=16m", "-v", tmp + ":/work:ro", "-w", "/work",
                   "python:3.12-slim", "timeout", str(timeout - 5), "python", "-I", "runner.py",
                   "case.json", marker]
            kw = {}
        else:
            import resource

            def limits():
                os.setsid()
                resource.setrlimit(resource.RLIMIT_CPU, (timeout, timeout))
                resource.setrlimit(resource.RLIMIT_FSIZE, (1 << 20, 1 << 20))
            cmd = [sys.executable, "-I", "runner.py", "case.json", marker]
            kw = {"cwd": tmp, "preexec_fn": limits, "env": {"PATH": os.environ.get("PATH", "")}}
        try:
            p = subprocess.run(cmd, capture_output=True, text=True, timeout=timeout, **kw)
        except subprocess.TimeoutExpired:
            return [False] * len(tests)
        for line in reversed(p.stdout.splitlines()):
            if line.startswith(marker):
                return json.loads(line[len(marker):])
        return [False] * len(tests)


def cmd_score(a):
    data = {r["id"]: r for r in read_jsonl(a.data)}
    gens = read_jsonl(a.gen)
    rows = []
    for g in gens:
        r = data[g["id"]]
        res = run_case(extract_code(g["output"]), r["tests"], docker=not a.no_docker)
        rows.append({"id": g["id"], "all_pass": all(res), "frac": sum(res) / len(res),
                     "finished": g.get("finished", True)})
    write_jsonl(a.out, rows)
    n = len(rows)
    print(json.dumps({"n": n, "strict_pass@1": sum(r["all_pass"] for r in rows) / n,
                      "mean_test_pass": sum(r["frac"] for r in rows) / n,
                      "unfinished": sum(not r["finished"] for r in rows)}, indent=2))


def cmd_compare(a):
    A = {r["id"]: r["all_pass"] for r in read_jsonl(a.a)}
    B = {r["id"]: r["all_pass"] for r in read_jsonl(a.b)}
    ids = sorted(set(A) & set(B))
    b = sum(A[i] and not B[i] for i in ids)   # only the first run passes
    c = sum(B[i] and not A[i] for i in ids)   # only the second run passes
    n = b + c
    # exact two-sided McNemar test (binomial, p = 0.5) on the discordant pairs
    p = 1.0 if n == 0 else min(1.0, 2 * sum(comb(n, k) for k in range(0, min(b, c) + 1)) / 2 ** n)
    print(json.dumps({"n": len(ids), "a_pass": sum(A[i] for i in ids) / len(ids),
                      "b_pass": sum(B[i] for i in ids) / len(ids), "only_a": b, "only_b": c,
                      "mcnemar_exact_p": p}, indent=2))

def check(kind, text):
    if kind == "json":
        m = re.search(r"\{.*\}", text, re.S)
        try:
            d = json.loads(m.group(0))
            return "name" in d and "age" in d
        except Exception:
            return False
    if kind == "short":
        return 0 < len(text) < 300
    return re.search(kind, text) is not None

Procedure

  1. A. EvalPlus, base and tuned model, same backend, greedy: evalplus.codegen --model MODEL --dataset humaneval|mbpp --backend vllm|hf --greedy, then execute in the ganler/evalplus Docker image (eval.sh section 1b; one-line evalplus.evaluate forms from the README are in section 1). The tuned model is the MERGED model folder, which is what gets published; bf16 merge rounding can change outputs slightly.
  2. B. Regression check, part 1: evalplus reports both the base tests (HumanEval, MBPP) and the base-plus-extra tests (HumanEval+, MBPP+). The base-test line is the HumanEval regression check against the base model.
  3. C. Held-out slice: 300 questions with 10 generated asserts each that the model never trained on. Generate greedily, extract the first python block, run all asserts per question in Docker (python:3.12-slim, no network, read-only, 256 MB, 64 pids, uid 65534, from data/snippets.json docker-hardened-sandbox). First run the dataset's reference solutions through the same sandbox and drop rows that fail. Report strict pass@1 (all 10 asserts) and mean assert pass rate, plus McNemar p.
  4. D. Regression check, part 2: 12 general sanity prompts (factual answer, JSON-only output, translation, SQL, JavaScript, arithmetic, bash, a bug fix, a stop-after-hello prompt) with regex checks, greedy, 256 new tokens; also count answers that never emit an end token.
  5. E. Training diagnostics: train and eval loss curves, mean_token_accuracy, grad_norm (TRL logs these). Read 10 generations by eye before trusting any number.
  6. F. Keep decoding settings identical: for Qwen the model's generation_config.json sets repetition_penalty 1.1 and the evalplus 0.3.1 HF backend passes only do_sample and max_new_tokens (768), so that file is silently part of the evaluation; copy it unchanged into the merged folder (save_pretrained does). vLLM reading the same file by default was not verified.
  7. G. Do not tune hyperparameters on HumanEval+ or MBPP+. Select on validation loss and the held-out slice, then run EvalPlus once.

What counts as success

  • SUCCESS (our thresholds, chosen from the noise arithmetic above, not from a source): held-out strict pass@1 up by at least 3 points with McNemar p below 0.05, AND HumanEval+ and MBPP+ each no lower than baseline minus 2 points (about 3 HumanEval problems), AND the HumanEval and MBPP base-test lines no lower than baseline minus 3 points, AND sanity prompts passed at least baseline minus 1 with no new answers that fail to stop. A gain of 2 or more points on both EvalPlus sets would be notable but needs 3 training seeds before you believe it.
  • NO CHANGE: every delta inside about one standard error (HumanEval+ under 3.7 points, MBPP+ under 2.5, held-out under 3) and McNemar p of 0.05 or more. This is a valid and likely result; report it as no detectable change and do not search for a better seed.
  • FAILURE: HumanEval+ or MBPP+ down by more than 3 points, or sanity prompts down by 3 or more, or new unfinished generations, or eval loss rising while train loss falls. Check first: chat template and eos token (<|im_end|>), learning rate too high, and whether the merged model equals the adapter model in outputs.

What to expect

  • Most likely: no statistically detectable change on HumanEval+ and MBPP+ (changes within about plus or minus 3 points), because the model is already instruction-tuned for code and the run is tiny. estimate
    Basis: The OpenCodeInstruct authors trained for 3 epochs on 5,000,000 rows (about 15M sample-visits) with full fine-tuning from the BASE model and got HumanEval+ 73.8 and MBPP+ 68.3 for Qwen2.5-Coder-1.5B against 66.5 and 59.4 for the Instruct model (arXiv 2504.04030 Table 3). This recipe sees 4,000 x 2 = 8,000 sample-visits, about 0.05 percent of that, with LoRA, which Biderman et al. found learns less than full fine-tuning on code (arXiv 2405.09673). Benchmark standard errors (3.7 and 2.5 points) are of the same size as the plausible effect.
  • A small in-distribution gain on the held-out slice is plausible (roughly 0 to 5 points strict pass@1), mostly from adopting the dataset's answer style and signature conventions. estimate
    Basis: Training and held-out rows come from one generator pipeline and the training answers are execution-verified. The held-out slice is in-distribution, and instructions in the dataset are evolved from shared seeds, so near-duplicate leakage makes this the optimistic measurement. No published number exists for this exact setup; the range is a guess. A held-out gain with no EvalPlus gain is the expected shape.
  • Regression risk is low but not zero: slight drops on HumanEval base tests or on general sanity prompts (for example answers that become code-only), and small shifts in verbosity. estimate
    Basis: LoRA forgets less than full fine-tuning on out-of-domain tasks (Biderman et al. 2024, sec. 4.2), but training only on single-turn code answers can still shift the model's habits. Sanity prompts and the base-test lines are there to detect it.
  • Larger gains need more data, a higher rank or a base-model start, not more epochs on this subset. estimate
    Basis: OpenCodeInstruct Fig. 3 and sec. 4.2: pass rate on MBPP rises with the number of samples up to 5M; Biderman et al. sec. 4.7: rank 256 on all modules for code. Variant B (start from Qwen2.5-Coder-1.5B base with --eos-token) is the closest reproduction of the paper's setup at small scale.
  • Time and memory: about 12 to 13 GB and 20 to 60 minutes on a 24 GB GPU; about 5 to 6 GB and 1 to 4 hours for the 0.5B laptop variant. estimate
    Basis: Arithmetic in hardware_tiers (parameters x bytes, the 6ND FLOPs rule, assumed sustained throughput). Not measured.
  • Held-out reference solutions will pass in the sandbox for nearly all rows, but a few percent may fail because of sandbox differences (Python version, missing packages, time limits). estimate

Stretch: execution-based RL Experimental

EXPERIMENTAL. Not executed. Reinforcement learning with execution feedback is an emerging practice; reward hacking and instability are common failure modes.

Starting from the SFT model (or the Instruct model), apply GRPO with a unit-test reward so the model is pushed toward programs that pass tests rather than programs that resemble reference answers.

Task set. Run prepare_data.py --rl-pool 3000 to get prompts with reward_tests (6 asserts) and holdout_tests (the remaining 4). Sample 8 answers per prompt from the starting model with the reward function and keep only prompts whose pass rate is strictly between 0 and 1 (all-pass and all-fail groups give zero advantage and no learning signal). Save as data/oci-rl-pool/pool_filtered.jsonl. After training, evaluate on the hidden holdout_tests and on EvalPlus; a rise in reward with no rise on hidden tests means reward hacking.

Reward. files['reward_fn.py']: unit_test_reward(completions, reward_tests, partial_credit=False, **kwargs) returns one float per completion. It accepts string completions (standard datasets) and message lists (conversational), extracts the first python block, runs the code plus each assert in a fresh subprocess with a wall-clock timeout, a process-group kill and Linux rlimits, and returns 1.0 for all-pass else 0.0. Self-test passed locally on Python 3.9 (pass, fail, timeout, sys.exit(0) trick, missing code block, partial credit). Derived from the checked code-reward-subprocess snippet in data/snippets.json.

reward_fn.py
"""Execution reward for GRPO (EXPERIMENTAL). Stdlib only.

Runs the model's code plus assert-style tests in a subprocess with a wall-clock timeout, a process-group
kill and (on Linux) rlimits. This is NOT a security sandbox: run the whole training job in a container with
no network and no secrets (see the Docker command in data/snippets.json, docker-hardened-sandbox).
"""
import json
import os
import re
import signal
import subprocess
import sys
import tempfile
import uuid

try:
    import resource  # POSIX only
except ImportError:  # pragma: no cover
    resource = None

RUNNER = r'''
import json, sys
case = json.load(open(sys.argv[1]))
ns = {"__name__": "solution"}
loaded = True
try:
    exec(compile(case["code"], "<solution>", "exec"), ns)
except BaseException:
    loaded = False
res = []
for t in case["tests"]:
    try:
        if not loaded:
            raise RuntimeError("solution did not load")
        exec(compile(t, "<test>", "exec"), ns)
        res.append(True)
    except BaseException:
        res.append(False)
print(sys.argv[2] + json.dumps(res))
'''

CODE_BLOCK = re.compile(r"```(?:python|py)?[ \t]*\n(.*?)```", re.S)


def extract_code(completion):
    """TRL passes a string for standard datasets and a list of message dicts for conversational ones."""
    if isinstance(completion, list):
        completion = completion[-1]["content"]
    m = CODE_BLOCK.search(completion)
    return m.group(1) if m else ""  # no code block means no reward


def _limits(cpu_seconds, mem_bytes):
    def apply():
        os.setsid()  # own process group so the whole tree can be killed on timeout
        if resource is None:
            return
        resource.setrlimit(resource.RLIMIT_CPU, (cpu_seconds, cpu_seconds))
        resource.setrlimit(resource.RLIMIT_FSIZE, (1 << 20, 1 << 20))
        resource.setrlimit(resource.RLIMIT_CORE, (0, 0))
        if sys.platform.startswith("linux"):  # RLIMIT_AS is unreliable on macOS
            resource.setrlimit(resource.RLIMIT_AS, (mem_bytes, mem_bytes))
            resource.setrlimit(resource.RLIMIT_NPROC, (64, 64))
    return apply


def run_tests(code, tests, timeout=5.0, mem_mb=512):
    """Return the list of per-test booleans. All False on timeout, crash or missing code."""
    if not code.strip():
        return [False] * len(tests)
    marker = "RESULT-" + uuid.uuid4().hex + ":"
    with tempfile.TemporaryDirectory() as tmp:
        with open(os.path.join(tmp, "runner.py"), "w") as f:
            f.write(RUNNER)
        with open(os.path.join(tmp, "case.json"), "w") as f:
            json.dump({"code": code, "tests": tests}, f)
        proc = subprocess.Popen(
            [sys.executable, "-I", "runner.py", "case.json", marker], cwd=tmp, stdin=subprocess.DEVNULL,
            stdout=subprocess.PIPE, stderr=subprocess.DEVNULL, text=True,
            env={"PATH": os.environ.get("PATH", ""), "PYTHONHASHSEED": "0"},
            preexec_fn=_limits(int(timeout) + 1, mem_mb << 20),
        )
        try:
            out, _ = proc.communicate(timeout=timeout)
        except subprocess.TimeoutExpired:
            try:
                os.killpg(proc.pid, signal.SIGKILL)
            except ProcessLookupError:
                pass
            proc.communicate()
            return [False] * len(tests)
        for line in reversed(out.splitlines()):
            if line.startswith(marker):
                return json.loads(line[len(marker):])
        return [False] * len(tests)


def unit_test_reward(completions, reward_tests, partial_credit=False, **kwargs):
    """GRPOTrainer reward function: one float per completion.

    `reward_tests` is a dataset column (list of assert strings); TRL passes every dataset column except
    `prompt` as a keyword argument. Binary by default (all tests pass = 1.0). Partial credit tends to be
    gamed by programs that satisfy easy tests, so turn it on only after looking at samples.
    """
    rewards = []
    for completion, tests in zip(completions, reward_tests):
        res = run_tests(extract_code(completion), tests)
        rewards.append(sum(res) / len(res) if partial_credit else float(all(res)))
    return rewards


if __name__ == "__main__":
    tests = ["assert add(2, 3) == 5", "assert add(0, 0) == 0"]
    good = "```python\ndef add(a, b):\n    return a + b\n```"
    assert unit_test_reward([good], [tests]) == [1.0]
    assert unit_test_reward([[{"role": "assistant", "content": good}]], [tests]) == [1.0]
    assert unit_test_reward(["```python\ndef add(a, b):\n    return a * b\n```"], [tests]) == [0.0]
    assert unit_test_reward(["```python\nwhile True:\n    pass\n```"], [tests]) == [0.0]
    assert unit_test_reward(["```python\nimport sys\nsys.exit(0)\n```"], [tests]) == [0.0]
    assert unit_test_reward(["no code here"], [tests]) == [0.0]
    assert unit_test_reward(["```python\ndef add(a, b):\n    return a + b if a != 0 else 1\n```"], [tests],
                            partial_credit=True) == [0.5]
    print("ok: pass=1.0 fail=0.0 timeout=0.0 sys.exit=0.0 no-code=0.0 partial=0.5")
grpo_train.py
"""EXPERIMENTAL stretch recipe: GRPO with an execution reward on a small, filtered task pool.

Config names read from TRL 1.18.2 source (trl/trainer/grpo_config.py) on 2026-11-25. Not executed.
Prerequisite: a pool of prompts with `reward_tests` (drive the reward) and `holdout_tests` (never used in
training, check them after training to detect reward hacking). prepare_data.py --rl-pool 3000 builds it;
then keep only prompts the starting model solves sometimes but not always (pass rate strictly between 0 and 1
over 8 samples), which you measure with the starting model first.
"""
from datasets import load_dataset
from peft import LoraConfig
from trl import GRPOConfig, GRPOTrainer

from reward_fn import unit_test_reward

ds = load_dataset("json", data_files="data/oci-rl-pool/pool_filtered.jsonl", split="train")
ds = ds.remove_columns([c for c in ds.column_names if c not in ("prompt", "reward_tests")])

args = GRPOConfig(
    output_dir="out/grpo-lora",
    num_generations=8,                 # completions per prompt (group size); default 8
    per_device_train_batch_size=8,     # num_processes * this * accumulation must divide by num_generations
    gradient_accumulation_steps=2,     # 16 completions per optimizer step = 2 prompts
    max_completion_length=768,         # default 512; code answers with an explanation need more
    temperature=1.0,                   # default 1.0: sampling diversity is the learning signal
    learning_rate=1e-5,                # LoRA; the TRL default of 1e-6 is for full fine-tuning. Untested guess.
    beta=0.0,                          # default: no KL term, no reference model
    loss_type="dapo",                  # default in 1.18.2
    scale_rewards="group",             # default
    mask_truncated_completions=True,   # exclude answers cut off at max_completion_length from the loss
    num_train_epochs=1,
    logging_steps=1,
    save_steps=50,
    log_completions=True,              # print sample completions: read them to catch reward hacking
    use_vllm=False,                    # True with vllm_mode="colocate" is faster on an 80 GB GPU
    bf16=True,
    seed=42,
    report_to="none",
    model_init_kwargs={"dtype": "bfloat16"},
)

trainer = GRPOTrainer(
    model="out/merged",                # start from the SFT model, or Qwen/Qwen2.5-Coder-1.5B-Instruct
    reward_funcs=unit_test_reward,
    args=args,
    train_dataset=ds,
    peft_config=LoraConfig(r=32, lora_alpha=64, lora_dropout=0.0, target_modules="all-linear",
                           task_type="CAUSAL_LM"),
)
trainer.train()
trainer.save_model(args.output_dir)

Hardware (estimate). Expected outcome. ESTIMATE: a rise in training reward is likely; a rise on hidden tests and EvalPlus is uncertain and, if it happens, probably a point or two. Published RL-for-code results use far more prompts and compute; do not expect them at this scale.

Risks

  • Reward hacking: programs that special-case the visible asserts; hidden holdout_tests and reading logged completions are the checks.
  • Same-process execution lets a program monkeypatch builtins; a stricter design runs tests in a separate process from the candidate and compares outputs.
  • Tests are model-written and can be wrong, which rewards wrong programs.
  • Zero-variance groups (all pass or all fail) waste compute: filter the pool first.
  • Untrusted code execution: container isolation is required.
