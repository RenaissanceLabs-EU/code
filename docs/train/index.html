Part two

How to train language models for code

Part one explained what code is. This part connects that understanding to the practical decisions in training a model: what capability to build, what data to use and why, how to turn it into a documented dataset, which tools to run, and how to tell whether the training worked. Every resource was verified against its source, and each page marks what is established practice and what is still emerging.

Read it in order for a first project, or jump to the step you need. For the end to end picture first, read how a code model is trained.

1

Choose the capability

Completion, instruction following, repair, repository editing, test generation, tool use. Then the approach: scratch, continued pretraining, SFT, preference, RL.

2

Choose the data

What raw code, instruction pairs, patches, tests, traces and synthetic data each teach, the tradeoffs, and how the forms of a program map onto training signals.

3

Find datasets

A curated starting set of training datasets, benchmarks and environments, with contents, languages, format, size, limits and evidence of use.

4

Build a dataset

A worked, runnable example from source files to a versioned, documented Hugging Face dataset: licenses, filtering, dedup, secrets, splits, contamination.

5

Pick tools

Collection, processing, tokenization, training, tracking, execution and evaluation tools, with a minimal setup and options for scale.

6

Run a first experiment

Fine-tune a small code model on a prepared dataset: base model, data, config, commands, hardware, evaluation.

7

Evaluate

Held-out tests, execution-based checks, repository tasks, regression checks, contamination, and running generated code in isolation.
