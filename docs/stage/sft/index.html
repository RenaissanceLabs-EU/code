Stage 02

SFT: instructions, reasoning, trajectories

Teach the format: follow instructions, explain, edit, call tools, solve step by step.

Who needs this

The first thing most teams run on an existing base model. Cheap, fast to iterate, and the stage where data quality is most visible in the numbers.

Decisions you will make

  • Instruction data versus reasoning traces versus agent trajectories. Pick by the goal: short answers and edits need instructions; competitive programming benefits from long reasoning traces; repository tasks need multi-turn trajectories.
  • Teacher model and license: synthetic datasets inherit the terms of the model that wrote them. Check each card.
  • How much data. Several published recipes get strong results with a few tens of thousands of carefully filtered examples, so start small and measure.

Pitfalls

  • Training on data generated from the benchmark's own problems (or paraphrases) gives inflated scores and a model that is no better in practice.
  • Unverified synthetic code often contains wrong solutions. Execute it or test it, and drop what fails.
  • Mixing too many styles can degrade formatting. Keep a chat template and a loss mask on responses only, and check outputs by eye.
